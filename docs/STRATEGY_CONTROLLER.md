# 策略控制循环

当前L1执行端对已受理但未落核心请求的独立证明，以及RPC耗尽期限后等待新context观察的边界，见 [已受理请求恢复](SIMULATOR_SUBMISSION_RESOLUTION.md)。通用NotFound仍不允许重发或释放预留。

usecase.StrategyController是每实例串行Tick，由调用方提供有界context和新的进程incarnation。构造不启动goroutine、领取租约、准备资金或开风险。Tick领取并续期真实策略lease；standby立即等待下一轮，不读输入、改状态或发交易。每轮请求配置的poll间隔，不能用工作成功触发无延迟重试。

新owner先持久RECOVERING关闭旧许可，再沿原业务键观察活动动作并同步OMS/核心订单。每轮最多观察8个动作，内存游标仅用于公平调度，授权与不确定状态都持久化。PENDING提交是尚未发送的旧目标，恢复时丢弃并重新计算；尝试过的DISPATCHING/WAITING/UNKNOWN只能查原键，NotFound也不代表可重发。未知提交会阻止新提交键，但保留受控撤单通道。P06.17只有在L1数据库能够证明原请求已不可能被受理、且封住旧键后才转NOT_ACCEPTED；没有该证明仍保持UNKNOWN，详见 [截止证明](STRATEGY_ACTION_RESOLUTION.md)。

当前版本/来源变更、非RUNNING状态、预算/对账或所选行情失效进入恢复，使用保护差分撤旧单，未确认取消继续观察。旧订单、核心订单和动作都收敛且新源健康后才激活requested配置并RUNNING，execution再评估许可。desired_running=false进入STOPPING；只有所有义务终态才STOPPED，原active配置保留。暂停的持久请求和管理操作由后续管理层接入。

正常报价读取当前typed参数、同一所选来源及核心资金/共享预算，调用纯Maker和Diff。完整目标集共同受总额度及单笔限额裁剪，按lot向下且不保留不足最小金额的单。当前资金在只读一致快照内读取：库存为真实基础币available+frozen，可规划资产为available加本实例核心订单实际尚余冻结；不估算旧订单费率，不加回其他实例冻结。该额度只用于规划，最终执行继续原子预留资金和四范围额度，并验证当前行情与双租约。

完整买单目标另受共享账户最低生效库存硬限减实际基础币总额、再减其他实例所有未终态买单剩余量的约束。UNKNOWN与INTENT继续纳入，未确认卖单不抵消买单敞口；本实例旧买单由完整目标集代表，Diff仍先确认旧单撤销，执行端独立重验。

一次Tick最多新派发一个命令。随机决策键先持久为动作，Attempt记录稳定RPC键与截止时间后才写调用；调用未知时不重试。订单列表按账户/实例/产品完整分页且最多200条，再按原client ID向执行端同步真实状态；观察不会制造owner或新业务键。取消优先于补挂，任何未确认取消/未知订单或活动动作阻止补挂。

P06.16把用例接入独立strategy命令的Deer账户任务及Nacos/mTLS。运行中新实例按显式账户发现，各实例分别取得策略lease；备用进程的实例控制器不处理输入/交易。并发控制请求造成生命周期或输入revision变化时，等待下一轮重新观察，不在该调用重发交易；真正交易键冲突继续报错。30分钟实际运行另行记录，见 [业务装配](BUSINESS_RUNTIME.md)。
