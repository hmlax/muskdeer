测试镜像固定 `nats:2.12-alpine@sha256:b270f5e2428354c0335612694d7dd2fb588148e567a5757fdff325ef9c9332e6`，实际容器输出 nats-server v2.12.15。独立随机测试 project，JetStream file storage 位于专用 tmpfs，token 为明确样例；只绑定 loopback 55441，监控端口仅容器内健康检查。原 PostgreSQL/Redis 仍分别使用 55439/55440；不操作已有容器和消息。

## 发布边界

- 配置为单一地址、已有 stream 和 `muskdeer.environment.service` 前缀，token 只通过环境引用。TLS 默认开启，校验主机名、最低 TLS 1.2；真实 TLS/生产权限尚未验收。
- 构造有总连接预算，DNS/TCP 使用构造上下文；初始 socket 受 context.AfterFunc 保护，取消/截止可中断无响应握手。连接完成停止并 join 已触发的取消回调、清除 dial 闭包，不保留调用上下文。禁用自动重连/发现服务器，初始拨号不会在构造返回后重用闭包。
- 工厂/健康只读取流，拒绝 missing、NoAck、sealed 或 Subjects 未显式包含 `<prefix>.>`；不在应用启动创建/更新 broker。部署端应配置持久化、保留、去重窗口、容量和授权。
- Publish 接收借用的类型化 Protobuf、版本化资源和稳定 ID。最多 max_inflight（1..1024）个发布；编码前限制 Proto 大小、编码后复查，max_message_bytes 为 1..1048576。准入、发布确认使用调用方/command_timeout 的较早截止。
- 添加 Msg-Id/预期 stream，等待并验证非零 Sequence 的存储 ACK。明确禁用 Publish 重试、重连缓存和隐式重连，无异步队列/发布接口。连接终止后安全拒绝，恢复监督/客户端重建后续接入。
- Receipt 只说明配置 stream 的存储及其窗口内重复状态。消息超时可能已落盘；同 ID 的 payload 指纹由持久化业务所有者验证，不把 broker 去重当作事务或业务恰好一次。

初始调用状态为：未准入→等待配额→发送/等待确认→获得存储回执，或进入失败/不确定状态。进程在发送后、确认前退出，数据库 outbox 仍必须保留待确认记录；确认后、更新 outbox 前退出会导致同 ID 再投。P04 实现该事务边界和 durable 指纹；P02.6 没有数据库发布状态或消费者效果提交，不能宣称关闭这些崩溃窗口。

## 测试

单元覆盖取消前无 I/O、6 个纯配置拒绝分支、单配额耗尽时 command deadline、资源/版本拒绝、静默握手后的取消关闭；Deer 注册可拒绝缺少消息依赖。全量 race/goleak 无新增忽略项。

真实 NATS 的 8 组场景：

1. 技术 Probe 的精确十进制字符串经过 Protobuf 存储/读取完全相同；subject/Msg-Id 正确；同 ID 同内容第二次得到 Duplicate/相同 Sequence；关闭后不能重开。
2. wildcard、缺 ID、nil message、超限 payload、预取消请求均拒绝，实际消息数不变。
3. 构造后将专用流改为 NoAck，Publish 在 40ms 截止失败，但 GetMsg 确认服务器已存一条；无自动重放。恢复 ACK 后由所有者显式使用同 ID 再投，得到相同序列的 Duplicate；另一个新工厂会拒绝 NoAck。
4. missing stream 构造失败且保留 ErrStreamNotFound，没有自动建流。
5. 使用不在已部署 Subjects 中的 namespace，初始化失败，避免“流存在但无法接收本服务消息”的假 readiness。
6. Deer 启动就绪后删除其独立测试流，实时 readiness 立即返回 ErrStreamNotFound，正常停止释放。
7. DeerApi 具有 PostgreSQL、Redis、JetStream，路由初始化失败后共享 publisher 已关闭；已有数据库/缓存回滚场景一并回归。
8. 无效 token 由真实服务器拒绝，保留 ErrAuthorization，外层错误不含 token。

原 PostgreSQL 模型 5 组、客户端 6 组和 Redis 6 组同时回归。测试端仅在临时 broker 使用管理 SDK 建流/改 NoAck/删流，生产客户端不暴露这些操作。

实际通过：make fmt、make verify（实际 go1.27.3、5 个生成物一致性、hz 双次生成/编译、格式/lint、4 项 Python、全部 Go 单元/race 与构建）、make integration、带 integration tag 的 go vet、27 份文档本地链接及 git diff --check。临时 PostgreSQL/Redis/NATS 三个容器和网络均已清理。
