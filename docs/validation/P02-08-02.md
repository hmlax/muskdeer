# P02.8.2：进程存活与依赖就绪

日期：2026-10-27。关联 R09、A02/A26 的健康与生命周期部分；完整 P02 尚未完成。

## 实现

Proto 增加可选 monitoring listener。各 Deer/DeerApi 可拥有独立的 loopback Hertz 监听，暴露 /livez、/readyz，返回固定 typed JSON 字符串，不披露依赖错误。非 loopback 在 I/O 前拒绝，监听请求期限须在停止预算内。公共 Hertz 构造/Date/context/drain 代码复用原 API 路径，API 业务监听和监控端口仍分别保留。

Live 代表 Run 尚未结束，包含启动/drain；CheckReady 同时检查所有监听和当前已配置依赖。短暂依赖故障只使 readiness 失败，不把健康探针变成重启风暴。标准 gRPC Health 改为 Check/List/Watch 都使用这一实时检查，聚合名及逻辑服务名同一状态。

Watch 必须有原有配置范围内的 native deadline，最多四条在途，额外请求立即 ResourceExhausted；每 250ms 轮询并只发送变化。未知 Check=NotFound、未知 Watch=SERVICE_UNKNOWN。没有进程后台探测循环，ticker/名额由每条流 handler 拥有，退出释放。

生命周期：依赖/监听启动→全部启动及依赖通过后就绪→停止先撤销就绪/注销→transport drain→关闭依赖→Run 结束。HTTP/gRPC 健康不能替代后续业务租约、风险/对账门禁。

## 验证

先编写健康行为测试并确认缺实现失败。真实本地 TCP/Hertz/gRPC 验证：未 Run 不存活；健康依赖时 ready/Serving；关闭真实 RPC 工厂后 HTTP ready=503、gRPC Check/List/Watch=NOT_SERVING，live 仍=200；未知服务及 Watch 容量拒绝；停止后 Live/Ready 均 false。原 stream native deadline 行为继续通过。

真实隔离集成扩展 API→Nacos→两个 mTLS 节点用例：独立监控端口初始 live/ready=200，工厂关闭后 ready=503、live=200，业务节点原有停 A/B 继续调用场景保留。全部 PostgreSQL/Redis/JetStream/Nacos 回归通过，临时四容器/网络已清理。

实际通过 make fmt、make verify（doctor 示例、Proto/hz 生成、格式/lint、5 项 Python、Go 单元/race/构建）、integration tag vet、make integration、文档/差异检查。公共 HTTP helper 提取后的静态选择器建议已修正，未禁用 lint；保留全量 goleak。
