# P02.4：PostgreSQL 真实客户端与依赖装配

日期：2026-10-26。关联 A02/A26 的依赖装配、A01/A23 的生成模型回归；本步骤不新增业务实体或生产迁移。

## 实现范围

Postgres Proto 生成配置，密码环境变量引用、TLS/搜索 schema、有界池与连接/会话超时；deer/postgres.Client 拥有 pool/GORM 和幂等关闭。GORM 无自动 ping、自动迁移或 SQL/参数日志，数据操作保持 WithContext + 生成 Model。

Deer 先初始化日志、再 PostgreSQL、再其他依赖；失败逆序释放。DB() 为借用访问且明确报告未配置。CheckReady(ctx) 检查当前生命周期与配置中的依赖，启动发布 ready 前重新检查 PostgreSQL。RPC/HTTP 注册回调接收构造 ctx 和当前 Deer，避免通过全局变量或未赋值构造结果取得依赖；这是开发中 Go 装配 API 的参数更新，构造函数和 Proto/RPC 业务线协议未改变。

## 实际验证

单元测试先确认缺少实现编译失败，再实现。覆盖已取消构造、7 个非法池/TLS/schema/超时分支、缺少密码引用、连接失败文本不泄露测试密码且保留网络原因，以及服务注册时要求缺失 PostgreSQL 的失败回滚。

make integration 在唯一 Compose project 的 PostgreSQL 16.15 中执行旧 P01 的 5 组场景，再以 race/goleak 运行新基础设施 6 组场景：

- 直接使用生成 StorageProbe 真实读写 38 位 decimal 字符串、Id/必填时间与 NULL 删除时间；重复关闭不重开连接。
- max_open_conns=1 时占住唯一连接，第二次 Ping 的调用方 deadline 生效，并观测池等待计数。
- 真实行锁阻塞更新，PostgreSQL statement_timeout 返回 SQLSTATE 57014，价格保持原值；不靠 sleep 或假驱动模拟超时。
- RPC 注册回调取得当前 Deer 的已初始化 DB 和构造 deadline；运行后健康检查通过，注入池关闭后 CheckReady 报不可用。
- API 路由装配失败保留原始错误，复用 Deer 的 pool 已关闭、连接计数为零。
- 错误密码被真实服务器以 SQLSTATE 28P01 拒绝，原始服务器原因可通过 errors.As 取得，顶层错误文本不暴露测试密码。

测试 DDL 仅创建隔离测试 schema muskdeer_p02 的技术 fixture，其表含四个公共字段；脚本最终清理自己的容器/网络，未操作用户已有基础设施。业务操作全部显式绑定生成 Model。

已通过 make verify、make integration、带 integration tag 的 vet，以及最终回调必需依赖用例的格式/race/lint 检查；25 份项目/来源文档链接及 git diff --check 通过。未进行真实生产 TLS/凭据验收、生产迁移、容量压测，Redis/JetStream/Nacos 和业务进程仍未实现，完整 P02/A26 保持未完成。
