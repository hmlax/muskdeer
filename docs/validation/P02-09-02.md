# P02.9.2：请求编号与 JSON 日志关联

日期：2026-10-27。关联 R09 的请求关联；完整 P02 仍在进行。

## 范围

新增 requestid.ID、私有 typed context key、HTTP/gRPC 入站规范化和响应头、unary 工厂出站 metadata 透传、根 JSON 日志字段。接受单个 1–64 字节 ASCII 字母/数字/点/下划线/连字符；缺失、非法或多值使用 crypto/rand 的 128 位 hex 值。不回显非法值，请求编号不授予身份、权限、幂等或执行所有权。

HTTP listener 与 monitoring 均传递请求 context/native deadline；gRPC unary/stream 保留底层取消/期限，stream wrapper 只保存验证后的 ID，每次从 delegate 取得 context，不保存请求 context。出站工厂优先采用已绑定 context ID，否则规范化出站 metadata/生成新值；复制 metadata 后覆盖该键，不修改调用者原数据。

日志在 context 存在编号时将其加入根字段 request_id，普通/分组/预绑定 logger 均保留根身份；用户 root 属性不能伪造该字段。static attr 在 WithAttrs 时冻结，保留 eager LogValuer/redaction 语义；有 context 的记录按保存的不可变 group/attr 操作加入动态根 metadata，无 context 保留预构建 handler。旧 Kratos key/value 接口中的显式 request_id 继续验证并绑定，未将编号加入指标标签。

## 验证

typed ID 的合法/非法/长度/随机独立值、context deadline/取消保持；先验证分组日志会错误采用 spoofed 值的失败场景，再实现根字段保护；原日志身份、decimal、敏感字段、轮转、并发与关闭回归保留。

真实本地 HTTP 验证合法、缺失、非法、多值四种请求，响应头/body/分组根 JSON 日志一致，独立请求不共享生成值。真实隔离 API→Nacos→mTLS gRPC 场景补充固定 edge ID，必须从后端 gRPC response metadata 返回相同编号，否则 API 探针失败。

初次尝试 Kratos 应用 Logger 选项触发全局 SetLogger/data race；该设置已撤销，保留并发/race 检查。库构造器不修改全局 logger，完整框架日志桥接由后续独立进程入口统一初始化，不将此处请求日志关联冒充全局桥接完成。

实际通过 make fmt、make verify（doctor、Proto/hz、格式/lint、7 项 Python、Go 单元/race/构建）、integration tag vet、动态端口完整 make integration 及文档/差异检查，保留全量 goleak，临时四容器/网络已清理。trace/exemplar、管理 API envelope 中的 request_id、框架全局日志和业务进程仍待后续。
