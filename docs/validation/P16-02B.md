# P16.2B — 原生持久命令身份

2026-11-03；基线 `5551e2e`，分支 `codex/two-apps`。

新增 MySQL 命令日志组件和显式、增量的 version 1 SQL。复用原生 OsPersist 池的接口已准备；本步尚未接入订单服务发送路径，运行数据库没有应用此迁移。日志以 user/fund/client_id 唯一约束绑定不可变 typed 业务编码及固定原生订单 ID，只有插入并确认提交的调用得到发送权限。已有记录、提交错误和重复请求均不授予重发权限；查询按账户范围读取，已确认终态不能倒退。

`make native-himalaya-test` 实际通过：原生所有权组件 6 项测试，以及既有 infra MySQL 上的真实日志集成测试。测试只创建随机逻辑库，最终清理该库，不创建或停止基础服务，不使用现有账户表。

真实数据库断言覆盖 32 个并发竞争者只有一个发送资格、重复键返回同一原生 ID、改变业务内容被拒绝、提交后进程/回复丢失且重连后不重发、按旧 ID 恢复结果、终态不被晚到回复覆盖、跨账户读取拒绝、分页保留全部活跃身份，以及唯一索引缺失时版本号不能冒充可用 schema。

首轮并发测试实际复现 InnoDB duplicate INSERT 的共享锁升级死锁（1213）。修复为重复插入后回滚该只读竞争事务，再查询已提交记录；没有自动重试交易发送或减少竞争数，原断言随后通过。没有注入 MySQL COMMIT 回复丢失，提交结果不确定分支仍需后续网关故障验收。

独立锁定 Rust 1.94.0/sqlx 0.9.0 工具链与依赖，组件 `cargo clippy --locked --offline ... --all-targets -- -D warnings` 和格式检查通过。依赖锁沿用 Himalaya 已有锁定版本并裁剪，未修改原生依赖。证据在 `.cache/himalaya/native-journal{,-red,-clippy}.log` 与 `native-standalone-checks.log`。未升级容器、运行策略、撤单、充值或平仓；完整接管继续等待网关和四服务接入。
