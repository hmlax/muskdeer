# P16.2C — 关闭旧入口绕过并保留原生减仓

2026-11-03；基线 `3fa13a5`，分支 `codex/two-apps`。

新增回归先实际复现：已有账户所有权后，原生普通 Place 仍能绕过新 producer RPC。修复后，只要撮合启用开发接管，最终执行点拒绝接管资金账户的普通下单，包括 fund 默认别名；没有 producer proof，不能通过换旧 RPC 路径下单。其他资金账户仍沿用原通道。

原生清算另用 ServiceAuth 的独立 administrator 身份调用显式 SystemReduce。该通道限定本轮测试账户/交易对、IOC、有限准入期限与原生订单 ID，不接收任意挂单。实际撮合执行时先持久撤销 producer 的账户和策略权限，再持有 guard 完成减仓效果。订单服务在原有清算链路已持久准备订单并冻结平仓量之后，借用已有 matching channel 调用此通道；未接管账户的清算路径保持。Muskdeer 接入只使用普通 service 凭据，不需要管理员凭据。

实际验证：修复前旧入口测试失败；修复后的 `cargo test --locked --workspace --all-features --no-fail-fast` 退出 0，1695 passed、0 failed、38 原有 ignored。新增断言涵盖旧入口拒绝、原生 IOC 成交及旧双 proof 撤销、普通 service 身份不能进入系统通道。matching-engine/order-service 的格式检查通过，独立组件/真实 MySQL 日志目标通过。严格原生全包 Clippy 的既有诊断仍保留，没有将其宣称通过。

本轮改动通过前像哈希检查后直接写入两原生项目，增量及前像摘要保存在支持目录；未覆盖原有业务 diff，未升级容器，没有实际下单、撤单或仓位副作用。下一步仍需撮合目标拥有的失联撤单与恢复保护、订单 Gateway 绑定及四个 Go 服务接入；完整接管尚未完成。
