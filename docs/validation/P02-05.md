# P02.5：Redis 缓存装配

日期：2026-10-26。关联 R09、A02/A26 的依赖装配部分；不表示完整 P02 或交易业务完成。

## 范围及依赖

新增 Redis Proto/生成配置、deer/redis.Client、Deer.Redis() 及启动/运行时 PING。日志→PostgreSQL→Redis→业务依赖按序获取，停止逆序释放；DeerApi 复用同一实例。工厂同步校验、复制配置、解析环境变量口令并探测连接，无 getter 懒加载或全局客户端。

固定 [go-redis v9.23.0](https://github.com/redis/go-redis/releases/tag/v9.23.0)，BSD-2-Clause，作为已约定 Redis 的实际 SDK；许可证位于上游 LICENSE。该版本最低 Go 1.26，本项目实测使用固定 go1.27.3。模块选择同步更新 cpuid/v2 至 v2.4.0、uber/atomic 至 v1.12.0、x/sys 至 v0.48.0；go.sum 包含上游测试依赖，未向业务引入另一组测试框架。既有生成、Sonic、Hertz/Kratos、GORM/pgx 与日志测试随完整门禁回归。

测试服务固定 `redis:7.2-alpine@sha256:f8548b29a1f1cb358b5fcfec1e0126beab57ad15776c1e87623f865579f16c5a`，容器内实际输出 Redis 7.2.16；PostgreSQL 仍为 16.15。每次使用独立随机 Compose project、tmpfs、明确测试口令及 loopback 55439/55440，finally 清理自身容器与网络，不连接既有基础设施。

## 契约

- standalone 缓存仅暴露 Get/Set/Delete/Ping/Stats，值为 string；业务小数保持十进制字符串，不替代权威资金、订单或 fencing。
- key_prefix 至少环境/服务两段；所有相对键自动加前缀，副本可共享，服务之间隔离。业务键还需含资源类型。
- TTL 必须是正整数毫秒，拒绝永不过期及精度被截断的输入。
- pool_size 1..1024，并设置硬 MaxActiveConns/MaxConcurrentDials；禁用额外 pipeline pool、命令重试及重复 dial 尝试，Protocol 2，停用维护通知/身份协商。失败 dial 的 TCP 恢复探针不是业务命令重试。
- 五种 duration 显式为正；命令使用调用方和 command_timeout 中较早的 deadline，已取消上下文拒绝执行。socket 截止先于 context.Err 发布时，仍保留 DeadlineExceeded 和底层网络原因。
- TLS 默认开启、校验主机名且最低 TLS 1.2；可配置根证书，测试环境明确关闭。口令仅通过环境变量引用，错误文本隐藏地址/口令且保留 errors.Is/As 原因。
- SET 超时是结果未知，本层不重放；不能从超时推断服务器没有写入。ErrNotFound 与依赖故障区分。

## 实际验证

相关单元测试覆盖构造前取消、5 个无 I/O 配置拒绝分支、默认 TLS/显式关闭冲突、单连接失败回滚、缺少必需缓存的注册失败。完整 race 与 goleak 不含新增忽略项。

真实 Redis 的 6 组场景：

1. 38 位精确字符串读回；同前缀第二实例可读、其他服务不可读；服务器 PTTL 正值且不超过指定 TTL；无效 TTL 不产生键；实际过期、删除及关闭后拒绝重开。
2. 专用测试服务器 CLIENT PAUSE 后，SET 在调用方 40ms deadline 内失败（含调度余量），保留 DeadlineExceeded；不重试、不对结果作未写入断言。
3. 单连接由暂停请求持有，第二请求等待后在 40ms deadline 失败，连接总数始终为 1。SDK WaitCount 只计成功获得连接的等待，因此取消场景改用实际等待时长和硬连接数断言，未忽略失败。
4. RegisterGRPC 获得已初始化缓存；Run 后实时健康成功，注入缓存关闭后 readiness 失败，正常停止回收。
5. DeerApi 路由装配返回错误，借用的缓存被关闭且连接数归零。
6. 错误密码被真实服务器以 WRONGPASS 拒绝，保留类型且外层错误不含口令。

原 5 组 PostgreSQL 模型场景及 6 组 PostgreSQL 客户端场景同时回归。测试仅对临时 Redis 使用管理命令，不向业务暴露无前缀命令。

实际命令全部通过：make fmt、make verify（精确版本、生成一致性、hz 双次生成编译、格式/lint、4 项 Python、全部 Go 单元/race 与构建）、make integration、带 integration tag 的 go vet、26 份文档本地链接及 git diff --check。测试 project 的两个容器与网络均已清理。

## 审查发现和边界

上游连接池在失败 dial 达阈值后启动恢复探针，Close 不 join 正在等待的一秒定时器。首次 goleak 发现该残留；失败构造测试保持单连接触发条件，在 synctest 中为已知 connect_timeout 加一秒留出虚拟时间，随后要求所有子协程退出，外层 goleak 继续全量检查。未屏蔽协程、改大池来躲开失败分支或引入真实 sleep。Close 立即关闭池/已拥有连接，但该辅助探针可能在一个 dial timeout 加一秒后才完全退出；不宣称 Close 返回瞬间已 join 上游 worker。

网络 I/O 中途取消仍受 socket deadline 约束；Cluster/Sentinel、TLS 实连/证书轮换、生产凭据、容量、锁、PubSub、资金/订单缓存重建均未验收。SDK/框架默认日志的进程入口桥接、JetStream/Nacos、多节点发现、业务服务及管理页面尚待后续步骤。
