# P02.7.3：gRPC 双向 TLS 与服务身份

日期：2026-10-26。关联 R09、A02/A26 的内部通信边界；完整 P02 尚未完成。

## 实现

配置 Proto 增加 MutualTLS 文件引用及 GRPCServerSecurity 服务许可。非 loopback 的 gRPC 监听必须配置 mTLS；无 TLS 的例外仅限字面量 loopback，不接受 hostname 绕过。纯配置检查发生于公共依赖/文件/监听 I/O 之前。

rpcsecurity.Server/Client 使用标准 crypto/tls、x509，TLS 1.3、私有 PEM 证书/密钥和独立 CA pool。文件最多 1 MiB，错误不包含 PEM 内容。自身身份须为证书精确 DNS SAN，服务名采用小写 DNS 名并以 `.grpc` 结尾；服务器证书构造时须有效。服务端要求有效客户端证书链，按显式 1–64 个服务 SAN 许可匹配；客户端同时按 CA、TLS hostname 与精确被调服务 SAN 匹配。禁止通配许可及 InsecureSkipVerify，不使用来访 metadata 身份授权。

Deer 将 server TLS 配置交给既有 Kratos gRPC transport；配置、证书和许可在构造时复制，不引入全局状态、后台刷新或新依赖。启动读取错误沿原有逆序清理路径返回。

## 验证

先增加行为测试并确认缺少实现时失败，随后实现。实际 Deer/监听端口/gRPC 握手使用测试时生成的 Ed25519 CA 与 PEM 文件；不提交私钥或固定证书。

受信 `api.grpc` 调用 `execution.grpc` 成功并观察服务身份。六组拒绝场景均断言 RPC 失败且业务 handler 未运行：受信但未许可的 strategy 身份、另一 CA 签发的客户端、不信任服务端 CA、错误被调服务身份、过期客户端证书、缺少客户端证书。另验证自身证书身份错误、通配许可、过期服务器证书及公共明文监听/无 listener 配置拒绝。

实际通过 make fmt、make verify（精确 Go 1.27.3、Proto/hz 生成、格式/lint、5 项 Python、全量 Go 单元/race/构建）、integration tag vet、文档/差异检查，以及 make integration 的 PostgreSQL/Redis/JetStream/Nacos 全套回归。临时四容器及网络均已清理；TLS 场景使用真实本地 TCP/HTTP2，不依赖外部 CA 或生产凭据。

## 限制

这是本地真实 TLS/HTTP2 握手，不是生产 CA、证书分发或轮换证明。当前证书在构造时加载，轮换须重建实例；运行中到期会被后续 TLS 握手拒绝，健康/告警单独接入。证书认证是服务进程身份，管理用户 RBAC/审计与交易 fencing 不由此代替。gRPC 调用工厂、业务进程和生产环境仍未完成。
