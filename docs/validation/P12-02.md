# P12.2–P12.4：React、独立 admin/operator 与既有 infra

日期：2026-11-02。文档基线 6df6cea；代码提交以本分支 Git 历史和交付报告为准。工作分支 codex/two-apps。

## 交付

- 保留 React 前端，在新管理应用中仅展示 admin/operator 两种服务；TypeScript 与 Vite 构建产物已更新，OpenAPI 枚举同步生成。
- cmd/admin 独立启动 Hertz HTTP，cmd/operator 独立启动 Kratos/gRPC。两个入口分别解析参数，移除 cmd/muskdeer 及 role 分发；账户开通工具更名 adminuser。
- operator 在唯一 Deer 中装配行情、执行、策略和投影模块，借用同一套连接和生命周期。内部 gRPC 统一 operator.grpc，保留显式实例路由、租约与最终 fencing。未交付的 P09 定期任务仍未完成。
- 登录、会话、角色与 CSRF 在 admin 校验。业务请求只传递已校验的审计身份，不转发 token/CSRF；operator 的管理注册边界只接受认证过的 admin 服务及规范身份字段，不查询会话或重复管理角色权限。业务版本、幂等、资金及所有权检查保持。
- 历史模块回归以 internal/testservice 下各自的独立入口执行；正常取消不作为失败，取消与清理错误合并时仍保留失败，超时诊断维持类型和阶段。
- 测试复用 infra-postgres/redis/nacos/nats；创建并清理独立数据库、命名空间、临时认证账号及独立 NATS 测试账户中的消息资源，不运行额外基础设施容器。Redis 使用唯一前缀及仅作用于测试连接的延迟代理，不暂停共享实例。NATS 客户端新增用户名/密码环境引用，禁止与 token 混用。

## 诊断与边界

旧 token 专用失败夹具先触发混用认证门禁，已改为对实际启用的认证方式提交错误凭据，保留真实拒绝与密钥不泄漏断言。独立模块入口曾丢失正常取消及超时结构化诊断，已恢复并通过定向与完整原生回归。Nacos 2.4 的用户缓存异步刷新，通过临时账号的实际无 token 登录观察就绪后再测拒绝，不对现有管理员试错。

共享 NATS 原有 8 GiB 文件额度已全部预留，经授权添加独立测试账户，并将服务总上限扩至 9 GiB、重启应用配置；既有流和消费者不改。测试全程未新增 PostgreSQL/Redis/Nacos/NATS 部署。

过程中宿主磁盘耗尽使 Docker 文件系统只读；清理本项目约 39 GB 可再生成 Go 编译缓存，经授权重启 Docker Desktop，确认原容器恢复后重跑验收通过。日志与凭据仅保留本地缓存，未提交真实凭据。

当前混合工作区的原有未提交平仓事件断言失败保持，不将它或未提交迁移纳入本次完成范围。完整十五组历史浏览器、固定三十分钟场景及生产环境本步未运行；短 smoke 不代表三十分钟验收。完整 P07/A27、P08–P11 与 L1/L2/L3 不因此完成。远程 CI 未作为本地验证结果，集成/浏览器 CI 需已有 infra 的自托管 runner。
