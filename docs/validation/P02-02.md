# P02.2：Deer/DeerApi 构造与真实 transport 生命周期

日期：2026-10-26。关联 R09、A02/A26 的公共封装部分；业务服务与基础设施装配尚未完成。

新增 ServiceConfig/Listener Proto 与生成类型，配置复制及初始化前校验。NewDeer 装配独立 Kratos/gRPC，NewDeerApi 组合单个 Deer 并装配 Hertz；构造时预留监听端口，注册回调返回错误立即回滚。Run(ctx) 管理就绪、取消、停止与最终资源释放，cleanup 支持未运行、运行中及已停止状态，重复/并发调用只释放一次。

## 行为验证

- 两个独立实例均可通过真实 TCP 调用 gRPC health；关闭一个不影响另一个。
- 注册生成的 ArithmeticProbe RPC，实际调用得到精确 string 小数 0.02；RPC 上下文携带正确服务名、实例 ID 和版本，修改构造输入不影响服务身份。
- gRPC health Watch 无 deadline 或 deadline 超过配置时返回 InvalidArgument；配置内的原生 deadline 到期返回 DeadlineExceeded，不留下无限期 stream。
- gRPC 端口占用、RPC 注册回调失败、HTTP 端口占用及路由回调失败均释放已获取依赖并保留错误；无效配置在初始化副作用前被拒绝。
- 未启动时 cleanup 释放端口；运行取消、重复 Run、重复 cleanup、8 个并发 cleanup、无 listener 的生命周期均按契约处理。
- API 通过真实 HTTP 收到 string 小数响应和有截止时间的上下文；同进程依赖只初始化/释放一次，HTTP/gRPC 两个端口最终都释放。
- 正常停止和 HTTP 监听意外关闭时，已接受请求完成后才释放依赖；监听异常清除 readiness 并由 Run 返回错误。

先添加服务行为测试，确认实现缺失导致编译失败，再实现构造与生命周期。新增回归测试曾暴露：异常监听结束不保证已接受请求结束、Kratos 在 transport 错误后的排空过程晚于错误触发时间。实现增加即时停止/撤销就绪通知，并始终排空底层 transport，未降低原断言。

Hertz 首轮真实 HTTP 测试还发现默认 Date ticker 与可选断连感知的进程级 poller 无实例级关闭入口。实现改为逐响应 Date 并不启用该可选 poller，完整 goleak 检查保留，无 goroutine 忽略项。即时感知客户端断开尚未提供，HTTP 请求上下文有显式 deadline。DeerApi/NewDeerApi 的用户命名要求通过两处精确 revive 规则例外记录，其余 lint 规则未关闭。

## 实际检查

固定 Go 1.27.3 下，make verify（生成一致性、hz 双次生成/编译、格式、lint、4 项工具链门禁、全部 Go 单元/race 与构建）、python3 scripts/go.py test -race -count=10 ./deer、python3 scripts/go.py vet ./... 全部通过。deer 包共 24 项顶层测试，其中配置拒绝覆盖 7 个分支；goleak 无忽略项。

make integration 的独立 PostgreSQL 16.15 及 5 组数据库场景通过，临时容器/网络已清理，未操作既有基础设施。现有 PostgreSQL 技术 fixture 只作回归，不代表本步新增业务存储或生产迁移。20 份项目文档本地链接检查及 git diff --check 通过。

本步骤未连接真实 Nacos、Redis、NATS，也未提供生产部署、交易服务、鉴权或完整健康/监控。A02/A26 和整个 P02 保持未完成。
