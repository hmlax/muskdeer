# P13.6：Wire 装配与 Deer 依赖注入

2026-11-03，基线 3b94abe，工作分支 codex/two-apps。验收目标：四个核心服务使用独立 Wire injector；deer.Deer 保存 Kratos App、日志和公共客户端，通过 With 选项注入已有依赖，保留单实例生命周期、健康检查及清理错误。

## 实现与所有权

- 四个 `<service>/cmd` 使用 main.go、wire.go、wire_gen.go 与 injector 测试；各自 internal/app 的 Config、WorkPlan、ServiceSpec、App ProviderSet 生成静态调用顺序。各 main 继续无参数、env/Nacos 配置、独立进程；没有按名称分发或共用业务工厂。
- Wire v0.7.0 固定在 go.mod require/tool 和 tools/versions.json。make wire 生成，make wire-check 比较且不写回；生成及 verify 流程包含 Wire 检查。wire_gen.go 全部由工具生成。
- Deer 保存运行中的 `*kratos.App`，继续持有 logger、PostgreSQL、Redis、JetStream、Nacos 和 RPC factory。Kratos App 在全部 transport 装配后、Run 时创建一次，保留运行上下文、worker 排空与同步清理；没有增加全局 logger 或单例。
- `NewDeer` 与历史 `NewDeerApi` 增加 `...Option`，旧三参数调用兼容；支持 WithDB、WithRedis、WithLogger、WithJetStream、WithDiscovery、WithGRPCClients。WithDB 接收项目 PostgreSQL client，DB() 返回原 GORM handle。选项接收已初始化、非 nil 的客户端，注入优先于配置创建；配置校验保持。
- 注入资源为借用，调用方在 Deer cleanup 后关闭；Deer 只清理自己创建的资源和本实例注册。借入资源在构造、启动、运行 readiness 中继续检查。Wire injector 接收 `[]deer.Option` 并透传，标准 main 传 nil 使用配置装配；四个真实 injector 都验证借入 logger 的透传及关闭后可用。
- 资金、幂等、状态机、最终 fencing、RPC 身份及原业务算法不变；业务 WorkPlan 在公共依赖就绪后同步装配，不在 provider 中启动 goroutine 或另开池。
