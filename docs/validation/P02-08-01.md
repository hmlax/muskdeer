# P02.8.1：严格配置加载与 doctor

日期：2026-10-27。关联 P02 配置/工具链入口；完整 P02 仍在进行。

## 实现

LoadConfig 从有界普通文件解析生成 ServiceConfig，使用严格 protojson，解析相对日志/证书路径，并在实例构造前复用 PostgreSQL、Redis、JetStream、Nacos、日志及 RPC 的纯配置校验。配置错误隐藏原输入值并保留可检查原因。纯校验与组件构造分开：前者不读取密码、PEM，不创建日志/连接；后者继续验证实际环境与网络。

增加实际 cmd/doctor、本地服务/API JSON 示例及 make doctor 集成。命令同时核对精确 Go 1.27.3 和所选配置结构/范围；错误非零退出，stdout 明确成功范围。无用户凭据、基础设施创建或业务占位 handler。

## 检验

先增加 LoadConfig 测试并确认缺少实现时失败，再实现。行为覆盖：相对日志/PEM 路径解析且不打开引用；未知 password 字段、错误数字类型、重复字段别名、尾随文档、缺服务身份、超过 1 MiB 和目录输入拒绝；解析与参数校验错误不回显秘密样例值；filesystem/取消原因保留。

doctor 测试通过有效 API 配置和包含秘密样例值的非法字段，验证退出码与安全输出。make doctor 实际执行精确编译器及两个文件检查。make fmt、make verify（Proto/hz 生成、格式/lint、5 项 Python、Go 单元/race/构建）、integration tag vet、文档/差异检查及完整 make integration 均通过；原四种基础设施、两节点与 API mTLS 调用链回归通过，临时四容器/网络已清理。初次 CLI lint 指出未检查诊断输出错误和 os.Exit 前 defer 无效，已处理写入错误并在退出前显式取消。

## 范围

本步是离线结构/范围检查，PEM 内容、密钥环境引用及网络在后续构造/健康阶段检查。未交付独立业务进程、健康/指标、开发部署或管理页面；不把示例配置误作可运行交易环境。
