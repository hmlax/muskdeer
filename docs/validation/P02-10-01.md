# P02.10.1 独立服务进程与框架日志

日期：2026-10-27。关联 R09、A02/A03/A26。

## 范围

- `cmd/muskdeer` 按 role/config 创建一个独立服务进程。api 使用 DeerApi，market/strategy/execution/portfolio/cron 使用 Deer。六份 loopback 本地配置不启用外部资源或交易业务。
- 进程入口在自有日志创建后、SDK 使用前安装一次 Kratos/Hertz 桥接；通用构造器默认不触碰 SDK 全局状态。停止或构造失败时逆序恢复桥接，再关闭日志。
- 框架日志保留 JSON 身份/级别/静态调用位置/参数数量，丢弃不受控格式文本及参数值。实际安全生命周期字段另行记录。Hertz 仅能通过 default logger 重建 system wrapper，适用于没有既有自定义 SDK logger 的新进程。
- SIGTERM/CTRL-C 正常关闭返回 0；独立运行或清理错误非零。纯 cancellation 与 cancellation+清理失败分别断言，防止错误被取消掩盖。

## 实际验证

- 六个角色分别启动独立的 race 测试子进程：每行 stdout 都可解析为带正确 service/instance 的 JSON，框架输出通过桥接；readyz 返回 200 后发送 SIGTERM，正常退出且 stderr 为空。
- Deer/DeerApi 构造失败时，已获取依赖先释放，桥接恢复时日志仍可写，随后自有日志关闭；原始失败保留。
- 真实构建产物启动两个独立 market 进程，PID 均与父进程及彼此不同；经认证 Nacos 发现两个端点，并使用 api.grpc 证书调用两个 market.grpc 的标准 mTLS Health。停止 A 后只剩 B 且 B 继续 Serving，再停止 B 后发现为空；检查两进程完整生命周期 JSON。
- `make fmt`、`make verify`、`python3 scripts/go.py vet -tags=integration ./internal/infrastructureprobe`、`make integration`、文档链接及 `git diff --check` 通过。完整集成保留原 PG/Redis/JetStream/Nacos 心跳和 API→发现→mTLS 回归，race/goleak 未屏蔽；隔离容器、网络和卷已清理。

## 限制

本步验证公共运行层。没有空业务 RPC、假 cron 任务或管理占位页面；交易合同、业务状态、管理前端及真实交易适配分别按 P03–P11 交付。开发持久资源和固定构建镜像仍待下一步，P02 保持进行。跨进程的 mTLS Health 不替代未来交易 fencing 或恢复验收。
