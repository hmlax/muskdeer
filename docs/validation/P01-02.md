## 实际断言

- Proto 生成结构直接被 GORM 解析，只有 9 个业务列，protobuf 内部字段未进入数据库；Id 为自增主键。
- 真实数据库元数据及写入证明 createAt/updateAt 为 NOT NULL，deleteAt 为 nullable；UTC 毫秒时间自动赋值，更新保留 createAt 并刷新 updateAt。
- 高精度值 12345678901234567890.123456789012345678 经 Proto、JSON 字符串、decimal 和 numeric(38,18) 往返不丢精度；JSON number 不能解码为价格字符串，decimal 的 0.1 + 0.2 等于 0.3。
- 0/false 显式更新、联合唯一键、主键唯一性、删除时间 NULL/零/有效时间往返及事务回滚通过；所有 GORM 数据操作显式绑定生成 Model。
- generate-check 在临时目录重生成并比较；人为加入差异时非零退出且原文件保持不变，恢复后无差异。
- PostgreSQL 使用随机独立 Compose 项目、127.0.0.1:55439 和 tmpfs；成功及失败路径均清理本次容器/网络，未使用既有 infra-postgres。

## 验证命令

make tools；make verify；make integration；python3 scripts/go.py vet -tags=integration ./...；git diff --check。纯 Go 契约测试 3 项，真实 PostgreSQL 场景 5 组，Python 工具链门禁 4 项。GitHub Actions 执行同一 verify/integration 流程；远程 CI 结果须以实际运行记录为准，不能由本地通过推断。

边界：StorageProbe 仅为技术验证 fixture；未交付业务持久化实体、生产迁移、自动软删除、Hertz/Kratos/Nacos 接入或任何交易链路。P01 尚需完成框架/生成器兼容验证后才能标 done。
