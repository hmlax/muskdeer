# P02.7.2：Nacos 实例发布与心跳所有权

日期：2026-10-26。关联 R09、A02/A26 的注册发现部分；完整 P02 尚未完成。

## 范围

在已有 context-bound Client 上增加 typed Registration、官方 v2 实例注册/注销、v1 light heartbeat，以及 Start/Stop 拥有的 Publication。配置 Proto 为 Nacos 增加可选 registration，既有只查询消费者无需发布；启用时必须有 gRPC listener、明确 advertise_ip 和 50–5000 整毫秒心跳间隔。生成代码由原工具链产生。

Deer 使用实际预留 gRPC 端口，在 listener 与依赖就绪后发布，再开放 readiness。启动注册失败或取消也由停止路径注销，处理服务器可能已接受的未知结果。后台心跳由 Publication 的 Stop 拥有，不保留启动请求 context。失败通知最多一次，Deer 保留错误并停止；停止先撤销就绪、取消并 join 心跳、注销，再停止 transport/依赖。

light heartbeat 不含完整 beat 注册载荷；缺失实例返回 20404 时不重新创建。HTTP 实例身份仍只有 scope/service/IP/port/cluster，metadata 中 Deer ID 不提供 fencing；并发 publisher 不得复用发布端点。交易执行权另由后续数据库租约/epoch 保证。

## 验证

单元/race/goleak 行为覆盖：持续心跳及恰好一次注销；丢失实例通知且不重复注册；注册失败仍执行注销；Stop 取消并 join 在途注册；未启动停止无网络请求且不可重启。纯配置校验补充无 gRPC listener、非法发布地址和心跳间隔。

真实隔离 Nacos 2.5.2 新增两个场景：

1. 两个独立 Deer 节点发布不同实际端口，以返回的地址调用 typed gRPC，验证十进制字符串 `0.1 × 0.2 = 0.02` 与节点身份。另注册无心跳对照实例，必须观察其被服务端判为失效，同时两个维护心跳的节点仍可见/就绪；最少跨越 16 秒、总预算 35 秒。停掉 A 后仅 B 可发现且继续服务。
2. 测试控制面删除一个已运行节点记录，下一次 light heartbeat 返回缺失；其 Run 非零退出、就绪撤销、实例保持不存在。

上述节点在同一个 Go 测试进程内，各自拥有 Deer、监听端口、HTTP 客户端及心跳；不宣称独立业务进程证明。原 PostgreSQL 5+6 组、Redis 6 组、JetStream 8 组、Nacos 查询 4 组场景一并回归。

强化对照测试首轮曾有一次通用查询失败，未得到具体状态；未扩大一秒命令预算、重试或削弱断言。补充仅输出安全状态/错误种类的失败诊断后，单独 Nacos 和完整四容器回归均通过，未复现，不将其归因于已修复的 CI JDK 故障。临时容器和网络已清理。

实际通过 `make fmt`、`make verify`（Go 1.27.3、5 个 Proto 生成文件、hz、lint、5 项 Python、Go 单元/race/构建）、integration tag 的 `go vet`、完整隔离集成及文档/差异检查。远程 Linux CI 以本步推送后记录为准。
