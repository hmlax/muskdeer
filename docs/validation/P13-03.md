# P13.3：env 引导 Nacos 配置

2026-11-02，基线 84fd86c，工作分支 codex/two-apps。验收目标：四个独立核心命令移除 flags 和本地 JSON，Nacos 连接从 env 获取，服务及业务运行配置从 Nacos 读取，复用既有 infra 并实际启动。

## 实现

- 四个 main 固定各自身份并调用自己的 runService，无命令行参数。LoadNacosConfig 使用有界、可取消的认证请求读取指定 namespace/group/dataId，严格解码 Proto JSON，拒绝远程连接覆盖、错误身份、未知字段和无效配置；没有文件回退。临时读取连接关闭后由 Deer 装配进程依赖。
- Nacos 连接、认证、TLS 和期限通过 env 提供；远程只保留 registration 元数据及服务/业务运行配置。其他密码继续使用 env 引用，私钥仍为证书文件。业务账本和持久策略版本仍由 PostgreSQL 管理。配置为启动快照，修改后显式重启。
- 新独立 readycheck 无参数，读取同一 Nacos 配置后只请求已有 monitoring，不构造第二个 Deer。维护工具默认 Nacos，migrate 保留显式 -apply；历史维护文件选项兼容保留，核心入口无此选项。
- Compose 只挂载各自证书目录，通过 nacos.env 和 NACOS_DATA_ID 启动；首次准备只发布缺失配置，不覆盖已有控制台编辑。tools profile 一次性维护容器只接 infra，避免争用运行服务的固定 IP。开发与原生进程测试同步使用实际 Nacos，测试结束删除自身配置。
