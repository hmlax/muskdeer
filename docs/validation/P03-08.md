# P03.8 模拟目标端事务 fencing

日期：2026-10-27。关联 P03、R09、A01/A12/A22/A23 的模型与目标约束部分。

- 新增 Proto 生成 SimulatorCommand/SimulatorOrder，版本5的唯一键、复合 FK、订单状态/冻结约束、不可变命令与事务结束 fencing。固定生成共13个 Proto Go 文件。
- 真实 PostgreSQL 验证正确授权提交命令及订单；策略 owner/epoch、执行 owner/epoch、过期 deadline 均在最终目标拒绝。新 owner 接管后旧进程命令拒绝，新 epoch 可提交；命令与订单无残留。
- 在有效命令和订单写入后、commit 之前受控修改数据库中的策略或执行租约到期时间，两种场景均在提交时报 fencing 错误并完整回滚。这覆盖 admission-only/立即检查遗漏的窗口，无随机 sleep。
- 不带订单效果的授权不能提交；已提交命令不可改写。高精度价格及公共字段往返通过；交易对、订单价/数量/成交量/冻结金额的 numeric NaN 全部拒绝。
- make generate/contract-check、fmt、make verify、integration tag vet、完整 make integration 通过，包括既有基础设施及 schema 升级/回滚回归、race/goleak；隔离 schema 与 Compose 清理完成。SQL 约束最后修改后由 integration 重新构建实际迁移二进制并验证。

本步直接使用生成 Model 验证模拟目标数据库，不包含资金账本、撮合处理器或 RPC 路由，不将 A12 全部或 P03 标完成。详见 [模拟器范围](../SIMULATOR.md)。
