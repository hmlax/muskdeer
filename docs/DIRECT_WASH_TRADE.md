# 当前 WashTrade 直发链路

2026-11-20 用户进一步要求当前开发合成成交跟随所选聚合成交源频率，并将数量向上量化。数据库 `wash_trade.interval_ms=0` 明确表示源事件触发，仅用于当前 development_only 聚合成交实例；正值仍表示原采样间隔，book 模式不接受零间隔。旧批次运行仍要求正间隔。

当前 `strategy_instances` 的 development_only WashTrade 使用：

```
market 订阅所选外部行情 → 内存保留最新一条 → strategy 计算 → execution 校验 → SDK WashTrade
```

- 不读取或写入开发成交表、批次、消耗序号、累计次数/名义量、持久化去重和回执。不向 Redis、消息队列或其他存储转移这些操作。
- agg_trade 按源成交量乘实例比例，当前直发链路向上对齐数量步长，不足一档取一档；上限先向下对齐后限制最终数量，不能因向上量化突破单次上限。旧批次历史计算仍向下对齐，原记录不重算；保持源方向及价格精度。book 保持原买卖交替、最优价及固定单次数量规则。配置上限不足一档或源事件过期时拒绝，不延长有效期或切换来源。
- 源触发模式逐条顺序处理有效成交事件，不使用定时采样，也不在 execution 重复施加间隔限频。market 与 strategy 分别使用有界64条缓冲承接短突发；market 缓冲满时明确以 ResourceExhausted 结束订阅，不能静默合并为最新一条，也不能构建无限积压。积压过期事件不发送。正间隔模式保留原最新一条采样规则。
- SDK发送前从GetMarket读取当前有效品种规则，以精确小数检查价格tick、数量step/最小量/最大量及最小成交额。quote_min_size按撮合实际合同使用固定10^-8报价币单位，与价格effectiveQuotePrecision独立；1000PEPEUSDT的50000000表示0.5 USDT。成功规则仅在内存缓存1秒，同品种并发冷读合并；无效/过期或读取失败时不发请求，不引入数据库访问。
- 低于最小量或最小成交额时返回SYNTHETIC_SKIPPED_MINIMUM，计入too_small，不计published/unknown/failed，不放大既有单次数量或突破上限。该源事件在当前进程内消费，后续有效事件继续处理；SDK明确拒绝时使规则缓存失效，下一源事件重新获取，不重试原写请求。
- 每个实例在当前 execution 生命周期内保留最后已处理源事件ID，拒绝重复/倒序事件；UNKNOWN源事件不再发送，后续新事件继续处理。重启不恢复历史，不承诺跨进程的持久去重。
- 每十秒输出 WASH_SOURCE_STATS，分别统计收到、重复、无效/过期、数量不合规、提交、成功、未知与失败；成功只按SDK实际回执统计。源触发代表没有固定人为限频，不代表在源过期、网络中断或SDK吞吐不足时仍能完整复制源流。
- 新的 typed `Execution.WashTrade` 不包含 run_id 或消耗序号。每次 SDK 请求有期限且不自动重试；回执丢失仅返回/记录 UNKNOWN 日志，不落库或补发。下一次只处理后续行情。
- 数据库仍保存模板、实例完整参数及启停；启动只读配置，不检查旧开发成交历史。后台修改只写配置及其操作审计。execution 单独每500毫秒批量刷新所有 WashTrade 的启停、修订、模板/品种有效性，事件处理只读内存；控制读取失败或超过2秒未刷新则暂缓发送。停止传播约半秒，已发请求可能完成。参数修改继续要求停止和明确重新装配。
- 行情订阅采用已有服务发现及 mTLS，只有 strategy/execution 身份可读。仅两个 market 订阅方法允许长连接，其他 RPC 保留期限合同。订阅不占 unary 并发槽，关闭时取消并等待接收协程退出。
- `development_only` 与既有不改变账户/订单/持仓的 SDK 接口保持，不新增真实账户对刷。

旧 `synthetic_tape_intents`、参数中的 run_id/maximum_events/maximum_notional、历史摘要和序号原样保留，仅供历史查询/旧回归。当前装配与管理入口不使用其运行门禁；旧 PublishSynthetic 批次 RPC 在当前实例服务拒绝。数据库结构版本仍为5，无迁移、清空、重建或伪造旧终态。

此约定替代旧文档中“当前开发执行必须持久化批次与消耗、按历史恢复”的要求；网格及旧审计回归的合同不变。做市铺单的零订单存储约定见 [DIRECT_MAKER_QUOTES.md](DIRECT_MAKER_QUOTES.md)。
