# 当前 WashTrade 直发链路

2026-11-09 按用户最新要求，当前 `strategy_instances` 的 development_only WashTrade 使用：

```
market 订阅所选外部行情 → 内存保留最新一条 → strategy 计算 → execution 校验 → SDK WashTrade
```

- 不读取或写入开发成交表、批次、消耗序号、累计次数/名义量、持久化去重和回执。不向 Redis、消息队列或其他存储转移这些操作。
- agg_trade 按源成交量乘实例比例、受单次数量约束并向下对齐数量步长；保持源方向及价格精度。book 保持原买卖交替、最优价及固定单次数量规则。过小或过期数据跳过，不补造数量或切换来源。
- 每个订阅最多保留一条待处理行情，按原配置间隔发送。同一个订阅内跳过重复或倒序源事件；重连/重启不恢复历史，不保证跨连接持久去重。
- 新的 typed `Execution.WashTrade` 不包含 run_id 或消耗序号。每次 SDK 请求有期限且不自动重试；回执丢失仅返回/记录 UNKNOWN 日志，不落库或补发。下一次只处理后续行情。
- 数据库仍保存模板、实例完整参数及启停；启动只读配置，不检查旧开发成交历史。后台修改只写配置及其操作审计。execution 单独每500毫秒批量刷新所有 WashTrade 的启停、修订、模板/品种有效性，事件处理只读内存；控制读取失败或超过2秒未刷新则暂缓发送。停止传播约半秒，已发请求可能完成。参数修改继续要求停止和明确重新装配。
- 行情订阅采用已有服务发现及 mTLS，只有 strategy/execution 身份可读。仅两个 market 订阅方法允许长连接，其他 RPC 保留期限合同。订阅不占 unary 并发槽，关闭时取消并等待接收协程退出。
- `development_only` 与既有不改变账户/订单/持仓的 SDK 接口保持，不新增真实账户对刷。

旧 `synthetic_tape_intents`、参数中的 run_id/maximum_events/maximum_notional、历史摘要和序号原样保留，仅供历史查询/旧回归。当前装配与管理入口不使用其运行门禁；旧 PublishSynthetic 批次 RPC 在当前实例服务拒绝。数据库结构版本仍为5，无迁移、清空、重建或伪造旧终态。

此约定替代旧文档中“当前开发执行必须持久化批次与消耗、按历史恢复”的要求；网格及旧审计回归的合同不变。做市铺单的零订单存储约定见 [DIRECT_MAKER_QUOTES.md](DIRECT_MAKER_QUOTES.md)。
