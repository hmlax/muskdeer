# 策略范围的紧急撤单

历史存档：本页管理 HTTP/Web 的应用和交付工具已于 P14 移除；保留原设计与验收记录。后端领域、RPC 和历史迁移是否仍存在，以当前源码和 PROGRESS 为准。

R08要求紧急撤单展示明确范围、原因及确认；[单笔撤单](ADMIN_CANCELLATIONS.md)不能扩大为全范围成功，Stop和[独立受限平仓](INTERFACES.md)也不是同一动作。P07.58交付领域请求和进度推导，P07.59–P07.61增加持久受理及有界工作，P07.62接入策略业务周期，P07.63提供内部只读历史/观测，P07.64接入typed管理gRPC，P07.65提供Hertz HTTP，P07.66提供实际浏览器确认、历史与结果页面。

P07.59另增Proto唯一来源的不可变受理结构与schema32；该步骤只有受理结构，未实现仓储或执行任务。执行进度尚未实现，不得把缺少进度行的请求推断为成功。迁移不回填请求，也不主动关闭风险或撤单；受理必须在同一事务写入真实风险关闭及范围审计。新表要求同一策略/操作者/会话/原因、风险修订一增及唯一证据，提交时重新检查会话和当前实际关闭状态。

P07.60接入内部受理/读取仓储：同一授权事务关闭风险、失效旧缓存、写风险关闭及范围审计和不可变受理，任何一步失败全回滚；复用原金融锁顺序。当前operator/admin加独立CSRF才能受理或重放，当前viewer可按策略读取历史。稳定键绑定规范化范围/策略/风险修订/原因，策略互斥后再次读历史，使并发同键得到原记录；不同内容或新键旧修订冲突，后续其他风险修订不重写历史，也不因重放重新关闭风险。

schema33与仓储恢复检查共同拒绝仍未归结的范围，即使暂时没有挂单/动作、市场已经新鲜。P07.60阶段尚无执行进度/完成证明，因此当时所有已受理范围保持待处理；后续以显式持久完成证明接入，不能把空数据或缺行当成功。受理不发执行RPC，不撤销、结算或释放LIVE/INTENT/UNKNOWN义务；完整执行接通前仍无对应HTTP/gRPC路由或页面。

P07.61增加内部有界收录/进度组件和schema34，尚未接到业务进程定期调用或公开管理入口。每次只处理一个范围、至多16个仍有义务的OMS目标，总待处理单笔收据遵守已有256容量；收录前等待所有未归结的新单动作，封存上界后单调推进游标。空页不代表最初无目标，已终态且零预留的历史单可跳过；数据库禁止游标漏掉仍有义务的目标。

范围派生的单笔请求持有可空parent关联，操作者/会话ID、历史角色、原因和策略只能来自原不可变受理与审计。已受理风险减少工作可在原操作者注销后继续，不能借此读取、重放或创建新的管理授权。派生只在持久前缀内成立；普通单笔请求的当前会话/CSRF校验不变，不能把既有请求改接到范围。收录只写元数据，不发送命令；既有StrategyOrderCancellations/StrategyActions及网关承担实际owner/epoch与UNKNOWN恢复。

P07.62在既有account worker中借用同一Deer数据库装配范围端口，不新增后台循环、资源或执行通道。只有取得并续租的执行者在恢复既有动作后，每周期至多推进一个范围，再走原单笔取消及最终fencing路径；游标耗尽后回到起点，游标丢失或进程替换不丢持久任务。未激活配置的实例也能处理空范围，但仍不能伪造下单/撤单权限。元数据收录本身不授予执行权，后续租约丢失仍由既有动作和最终网关拒绝。

P07.63提供内部当前viewer历史分页和单范围观测端口，复用同一数据库的只读RepeatableRead事务，将当前身份、不可变受理、存储任务证明及当前目标计数放在同一快照。按策略及ID游标、每页1–100条；历史页用一次有界任务批量查询，不按每条重算进度。有效但不存在的策略返回未找到，已存在策略的空历史返回明确空数组；缺失任务或不一致证明返回不可用，不能默认为成功。

单范围观测含数据库采样时间、存储结果及当前计数，读取不调用Prepare、不推进游标、不发执行RPC。ACCEPTED即使当前为空仍保持原存储结果；曾经FAILED的取消目标若后来成交并归结，其当前terminal可增加、failed可减少，原FAILED/修订/完成时间保持不变。任务结果和当前计数分别表述，不能以当前计数改写历史结果、恢复风险或证明持仓为零。

P07.64的[typed Proto](../deer/proto/rpc/strategy/v1/emergencies.proto)区分StrategyEmergencyCancellationControl与Query。RequestEmergencyCancellation显式携带scope、strategy_id、expected_risk_revision、原因、幂等键、当前会话和独立CSRF，只返回不可变受理。GetEmergencyCancellation提供存储Record、当前Progress及数据库观测时间；ListEmergencyCancellations返回有界历史。所有身份/修订/计数为int64，若经Proto JSON呈现为十进制字符串，不经浮点；没有JSON/bytes业务载荷。

服务借用同一Deer数据库，只有ManagementEnabled注册查询，ControlEnabled才另注册写入。API-peer mTLS、当前持久viewer/operator权限、原调用期限（最多5秒）、2KiB请求上限与请求及相关嵌套消息的未知字段拒绝均保留；使用原rpcclient单次调用、禁止透明重试，不直接发交易指令。返回前验证范围/完整确认、状态/可空证明/计数/分页及精确毫秒时间，私有存储错误统一公开分类。

P07.65沿用唯一DeerApi/已有strategy连接，提供POST /api/v1/strategies/{strategyID}/emergency-cancellations、同路径GET有界历史和GET /api/v1/strategies/{strategyID}/emergency-cancellations/{cancellationID}。POST仅接收scope、十进制字符串expected_risk_revision及原因，必须唯一会话Cookie、固定Host/Origin、独立CSRF和幂等键；拒绝重复字段、数字修订、未知字段、额外查询及非规范ID。受理和原键重放均为202加Location，即使任务已经完成，也不能把写回复当作终态观测。

两个GET只在queries开关装配，写入还需controls；借用原三秒期限、当前会话、no-store和typed错误，所有int64 JSON均为string。读取不推进任务；查询中的pending_submissions是当前实例未归结新单动作数，可能含后来工作，不能据此改写历史任务。仅查询模式同路径GET存在，POST为405；全部查询禁用时路径不存在为404。[OpenAPI](OPENAPI.md)包含三项操作及具体消息，不把HTTP闭环记为A27浏览器确认完成。

任务状态来自持久证明，而非读取时根据空计数推断。未收录完、待确认子请求、不明提交、缺失OMS投影的活动核心单或未释放预留都不能成功；已知失败目标仍保留义务。单笔历史失败后若订单后来确已终态且预留归结，范围可按当时权威事实达到终态目标，不改写单笔历史。可以因成交而终止，SUCCEEDED不等于每笔CANCELED或持仓清零。完成标记不能重新打开或改写，管理员恢复还必须通过原有当前资格/资金/市场/配置/目标检查；新风险、别的策略与后来风险修订不属于旧任务结果。

## 浏览器确认、历史与结果

策略详情的“查看范围紧急撤单”进入`/strategies/{strategyID}/emergency-cancellations`，查询开关开放页面；当前viewer只读，operator/admin还需controls能力才能显示确认表单。点击读取后展示明确策略、账户、交易对和独立风险修订；填写原因、手动输入相同策略ID并勾选确认后才能提交，不接受扩展账户或全局范围。

首次提交固定请求体与随机幂等键，未知结果保留原请求并锁定输入及历史导航，只允许按原请求重试。收到并验证受理后进入`/{cancellationID}`深链接；受理不显示为已撤。结果按存储任务展示，当前目标计数另行展示，不以零计数推断成功或恢复风险；每次请求最多6秒，自动轮询总计最多20秒，之后显式刷新。历史使用1–100后端合同，页面提供1/20/50/100条及ID游标，刷新保留URL分页。

ID、修订、计数与毫秒保持十进制字符串，比较用BigInt；超出安全日期范围的时间保留原串。拒绝缺字段、额外字段、非字符串整数、错误范围、不一致完成证明或重叠计数，错误后清除旧结果。原因按文本展示；会话撤销返回登录，浏览器存储不保存令牌或未知写请求，离开页面不撤回已受理工作。

`make admin-emergency-browser`用独有四项基础设施、真实API/strategy/execution和Chromium，覆盖提交后丢回复的原键重试、两个真实挂单待确认/竞态成交/最终资金结算、viewer历史及深链接、权限撤销，以及独立标注的协议损坏注入。已加入CI及`make e2e`第十五组浏览器流程，验证细节与资产SHA见[P07.66](validation/P07-66.md)。独立受限平仓和完整A27仍继续后续步骤。

## 词汇与约束

- scope=strategy：只针对明确strategy_id。账户和交易对从该实例读取；不接受隐式account/all范围，不触及共享账户的兄弟策略目标，也不隐式改变desired_state或配置。
- expected_risk_revision：确认该策略独立风险开关的修订，不是实例revision或单个订单revision。后续受理必须在同一授权事务中关闭新增风险、使旧风险授权失效，并记录幂等范围请求及审计。领域Normalize只验证输入，不冒充事务关闭或授权已实现。
- 幂等键：当前operator/admin的16–64 ASCII字符键；策略/明确范围/风险确认/规范化原因绑定同一不可变请求。新请求旧修订冲突，同键异内容冲突，原键重放返回历史收据，不能重新关闭后来已授权恢复的风险。
- 目标收录：必须持久、有界分页，并明确何时全部收录完成；一个空页或零目标计数不等于收录已经完成。不得因单页容量上限截断范围并宣称成功。
- pending_submissions：尚未确认结局的出站新单动作，包括未取得OMS身份的提交/UNKNOWN；不以不存在OMS记录证明未下单。即使当前目标全终态，存在这类动作也必须保持ACCEPTED。
- targets/terminal/failed：同一持久范围内的非负int64计数，terminal与failed互斥。terminal只可来自权威OMS终态及预留已归结的证明，可以是FILLED而不是CANCELED；failed仅表示明确的撤单失败，不释放仍有效的资金/敞口预留。UNKNOWN仍是待办，不能算terminal或failed。

## 进度推导

AdminEmergencyCancelProgress.State先检查计数一致性，用减法检查和的边界，禁止溢出或超额计数。未收录完、仍有pending_submissions、或terminal+failed少于targets时为ACCEPTED；全部归结且有明确失败时为FAILED，全部终态且无失败时为SUCCEEDED。已完成收录的真正空范围可以SUCCEEDED。

这些状态只描述历史工作进度，既不证明风险当前仍关闭，也不授予恢复/下单许可；SUCCEEDED不保证成交未发生或持仓为零。FAILED保留未达到撤单目标的义务，不能因批次结束释放预留。

## 后续持久化与执行验收

当前持久结构由Proto生成，版本化迁移和原子受理沿用既有金融锁顺序及最终执行端fencing。后续管理入口仍须复核当前用户/会话，授权关闭和批次原子提交，失败整体回滚；HTTP进程不得直接发送撤单。所有权替换只能恢复原键，不重造不明动作。

收录/执行未归结时，管理员恢复也须拒绝，不能仅靠临时零挂单窗口重新开风险。并发策略新增/提交与关闭的线性化、分页去重、共享账户隔离、原键重放、注销竞态、旧epoch、部分成交和撤单未知均须用实际数据库/进程行为验证。实现前不得将本领域组件记为紧急撤单功能完成。
