# 已受理取消的L1无效果证明

取消请求的终态和父订单的终态独立。原取消在REQUESTED/SUBMITTING/UNKNOWN且没有核心效果时，不能永久阻塞后续保护；普通查询缺失同样不能作为成功撤单的证明。

仅显式`NewSimulatorCancellations`启用共享数据库证明，业务execution装配选择它；通用`NewCancellations`保持原保守观察。只有原请求截止时间已过，才尝试READ COMMITTED事务，依次取得策略NO KEY UPDATE、核心instrument/account互斥及请求状态锁，等待在途核心取消结束，并以数据库时间重验期限。原account/core command key的全部CANCEL命令历史不存在，才将原请求记REJECTED/CORE_NOT_ACCEPTED并同事务写outbox。

该事务不更新父订单、余额或任何风险预算。原核心订单可以仍为LIVE，其冻结及四级风险预留全部保留。策略动作观察到原取消被拒绝后，可从当前订单/保护状态生成新的独立决策；真正完成停止仍需新取消实际到核心终态并被OMS确认。已存在核心取消命令则保持待观察，不能用新键重发它。

迁移22独立SQL重验无效果证明，永久封闭原核心取消键，保留解决历史，拒绝续期、清除错误、重开状态及删除/软删除。请求的核心键由原account/RPC key的既有SHA-256公式约束；索引只加速查询，不改变历史身份或释放资金。

提交和取消核心准入显式使用READ COMMITTED。数据库门禁在首次意图查询之前拒绝旧快照准入，避免REPEATABLE READ事务在等待互斥后仍看不到已提交的永久封闭记录；不依赖服务器默认隔离设置。此要求只属于当前L1合同，外部真实网关的截止/去重/权威否定合同仍须P11单独验收。
