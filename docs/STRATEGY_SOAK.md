# 策略真实时长验证

`make soak-smoke` 检查 12 秒驱动；`make soak` 执行固定 30 分钟真实时钟场景。两者先构建实际 CLI，启动本次独有的 Compose PostgreSQL/Redis/NATS/Nacos，端口仅绑定 Docker 分配的 loopback 地址。运行结束只删除本次项目及其卷，不使用开发环境或外部交易账户。

场景启动四个不同 PID 的 market/execution/portfolio/strategy，使用实际 Nacos/mTLS、数据库租约、OMS、资金冻结和 outbox/JetStream/inbox。行情是明确的 REPLAY；测试拥有的外部流动性驱动每两秒寻找一笔实时挂单，交替产生买卖 0.01 部分成交，再以同自然键验证核心去重。策略自己产生报价、撤单和补单，驱动不制造订单或补资金。

长运行配置显式准备 128 MiB、100,000 条、1 小时的有界测试消息流，保留 DiscardNew；原短集成的 4 MiB/1,000 条/10 分钟配置不变。长配置操作和 gRPC 客户端期限均为 3 秒、租约 10 秒、重放间隔 100ms，实例行情时效仍为 500ms；这些是本场景配置，不是生产 SLA。

每两秒在只读 REPEATABLE READ 快照检查：

- 核心冻结等于全部活动核心订单的冻结；每个核心订单均有先行持久 OMS。
- 全部 OMS 预留精确等于账户、策略、平台和交易对四级额度，且不超过各自上限。
- 实际 base 加全部非终态 BUY 剩余量不超过实例 hard limit 20，不用 SELL 抵消。
- 核心成交数等于驱动确认数；已追平的投影现金/持仓与真实核心资金一致；开放风险不能引用未对账投影。
- 双边报价以每100ms的实际核心活动订单读取观测，投影追平以两秒快照观测，间隙各不超过场景规定的10秒；快照同时记录两项gap。不能只在两秒快照时读取报价，因为它可能持续落在一秒最大报价年龄所触发的撤换阶段。停止后所有挂单终态、冻结及四级预留归零，成交/投影/inbox数量一致，费用/成本/PnL可由不可变事实精确重建。

产物在 `.cache/soak/<唯一运行 ID>/`：四份角色 JSON 日志、`run.log`、`progress.jsonl`、`result.json`、`metadata.json`。小数全部为 JSON string；元数据记录提交、工作区是否有未提交改动、实际工具链及场景类型。临时配置和 mTLS 私钥留在 Go 测试临时目录，不保存到产物。日志目录经过真实路径校验，不接受该根目录以外的目标。

30 分钟验收要求 Go 退出码 0、角色退出清理成功、实际驱动时间至少 1,800,000ms、至少 600 次真实部分成交及所有最终断言通过。`metadata.accepted` 仅在完整长场景通过时为 true；短场景无论成功与否均为 false。时长不支持环境变量缩短，不使用快进时钟。正常结束会等待所有角色；超时、中断或异常测试退出由 Python runner 只终止并等待自己创建的进程组，最后清理本次 Compose。

验收记录见 [P06.21](validation/P06-21.md)。驱动实现及短场景通过并不表示 A19 已完成，实际长运行结果另行记录；容量与端到端延迟仍须按 P10 测量。
