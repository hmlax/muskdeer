# 管理端身份与会话基础

P07.2交付持久化认证基础，管理HTTP/gRPC、登录页面及本地初始化命令在后续步骤装配，不能据此声明A18/A27完成。构造函数借用Deer数据库，不自动创建任何用户、密码或权限；Provision是受信任本地操作员入口，不可作为匿名网络接口暴露。

角色为viewer/operator/admin，能力逐级包含，未知角色或未知能力一律拒绝。用户名规范为小写ASCII 3..64字符（首位字母/数字，其余可含`_.-`）。密码不规范化，接受有效UTF-8的12..72字节；复用既有`golang.org/x/crypto v0.57.0`（BSD-3-Clause），使用bcrypt cost=12，不新增模块版本。边界及比较依据[固定版本官方文档](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/bcrypt)。每个借用仓储对象最多4个哈希操作，无等待队列，超额拒绝；取消在工作前及哈希后检查，哈希本身是固定成本的同步计算。

未知用户名执行同成本的公开dummy哈希比较，返回与错误口令相同的拒绝；dummy不对应身份，不能授予会话。登录失败次数保存在PostgreSQL用户行锁下，5次失败锁定5分钟，使用数据库时钟。拒绝在计数/审计事务提交后返回，避免失败计数被错误返回值回滚；锁定期间不重复写审计。无效凭据不在错误或日志中回显。

登录生成独立的256bit会话及CSRF秘密，使用canonical base64url（43字符）；数据库只存SHA-256摘要。会话固定8小时、以数据库时钟判断过期，不续期；每用户最多8个有效会话，新登录在同一事务撤销并审计最旧会话。注销和撤销不可恢复，原身份/期限和审计历史不可更新或删除。密码、角色、启用/退役变更必须增加credential_version，旧会话立即失效；每次读取仍核对当前用户状态与版本。

Identity和Authorize都是时点观察；Authorize额外核对独立CSRF和角色。管理业务写操作必须在自己的事务内重新调用带锁的授权读取，按用户SHARE→会话锁的顺序保持到受保护效果提交，不能在事务外调用Authorize后直接修改业务。注销一开始就取得会话NO KEY UPDATE，避免两个SHARE升级导致死锁。浏览器Cookie/Origin/CSRF请求头及业务RPC身份边界仍须在传输层接入时验证。

AdminUser/AdminSession/AdminAudit唯一来源为[模型Proto](../deer/proto/model/v1/admin.proto)，由gotag生成直接使用；迁移23创建实际约束。用户创建、成功登录、失败计数、会话/注销及相应审计同事务提交。认证审计只含actor/role/action/resource/reason，模型的可选before/after版本用于后续管理配置变更；不保存密码、哈希、bearer或CSRF秘密；持久化错误使用固定消息，内部cause可供受控分类。未实施的用户管理API不能从本基础接口推断已获远程授权。

验证及当前局限见[P07.2](validation/P07-02.md)。
