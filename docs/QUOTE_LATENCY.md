# 做市报价链路关联与耗时

当前做市目标会被邮箱合并，账户观察之后还可能采用更新目标。诊断必须记录实际发送时的 `cycle.plan`，不能把最初唤醒写入者的源帧、较新的安全检查行情或相同价格当作该订单的价格来源。

## 关联合同

strategy 为每个目标保留原 `QuotePlan.request_id` 并记录 `proposed_at_unix_nano`；execution 在不可变邮箱副本上自行记录 `accepted_at_unix_nano`。两项时间仅供诊断，不用于有效期、资金、启停或配置授权。旧字段编号和金融行为不变。

`Execution.SubscribeQuoteFlows` 是仅向 mTLS strategy 身份开放的只读服务端流。请求必须明确指定已配置做市品种，最多16个，不允许空请求扩成全量。每次真实 `SubmitQuote` 返回后，事件包含实际目标ID、源及序列、源事件/接收时间、原client_id、返回order_id、方向与精确价格、目标提出/接收时间、执行开始/准备等待、SDK开始/结束及安全结果分类。未知结果保留未知；有订单ID也不冒充成功。准备或风控阶段未调用SDK不会生成一条虚构发送记录。

事件不包含账户身份、余额、数量、凭据或完整请求，不进入订单数据库、Redis或消息账本。没有订阅且追踪未采样时不构造事件；采样追踪中的 `quote.flow` 事件携带同一目标/订单/源序列标识，策略追踪也记录目标ID。每进程最多4个诊断订阅，每订阅128条临时队列。发布只在内存复制，不等待网络或启动额外发单者；队列满后显式 `ResourceExhausted`，不悄悄丢样本、不改变原SDK结果。已溢出的请求在真正退出前继续占用订阅配额，避免慢网络绕过边界。退出清理自己的队列，不影响其他订阅或交易。

新RPC及字段须生成代码并配套发布strategy/execution；旧进程可能返回Unimplemented或缺少提出时间，不能混入完整链路样本。生产流中间件仅为认证strategy调用该诊断服务端流允许较长期限，客户端仍必须声明不超过15分钟的原生期限，以终止阻塞的SendMsg；其他流和金融RPC期限保持。配置、账户、实例参数和历史无需迁移。

## 盘口可见证据

SDK成功回执不是盘口可见，聚合档位也没有逐单ID。只读采集器同时订阅上述事件与原market-data全量盘口，使用既有撮合 `GetOrderOutcome` 读取原order_id。查询不重试金融请求，不修改撮合、WAL或订单；诊断查询须限速，记录其干扰和错误。

可接受的证据应明确区分：

- 实际采用的源序列、目标ID和SDK原订单ID完全对应。
- 盘口初始缓存快照剔除；后续使用同一撮合生成的快照序列及时间。
- 若快照时间是在创建快照之后才记录，单凭时间晚于回执仍不足以证明快照在该订单入簿之后开始。保守做法是先观察一个晚于回执的发布，再取其后的、包含该方向价格的快照，并在之后用同一引擎的原订单ID验证LIVE及正剩余量。结合不可复用身份、终态不复活及单一快照发布者，可证明订单在后一个快照中仍有效。
- 这得到“已证实可见”的耗时上界，包含保守确认等待；不能将它命名为首次可见的精确时间。记录时钟范围及客户端接收处理开销，不含页面渲染。
- 已成交/已撤、UNKNOWN、发布深度外或未观察到该价格、观测结束、队列容量及读取失败分别计数。无法确认不记为零，不只呈现成功订单而隐藏覆盖比例。查询时已终态也不证明订单从未上过盘口。

## 统计口径

源事件至接收包含源时钟偏差；本地接收至SDK发送、SDK调用与撮合快照生成可使用同机容器时钟。接收探针在宿主机运行时，需用只读服务器时间及请求起止给出时钟偏移范围；边界附近不能硬拼顺序。

按实际订单计算各段及同一条链的总耗时后再取分位数，不相加独立P95。轮次等待按实例和执行开始时间去重；最新源可能在等待期间才到达，不能把全部轮次等待再次加到这条源帧的年龄上。比较修复前后时同时报告观察窗口、样本数、错误/无发送轮次与行情负载，不把两段自然流量当作受控压测。

## 发布检查间隔与回执后快照指标

50ms之类的发布检查间隔只决定检查有变化盘口的节奏，不保证每个币固定频率产生新帧；实际循环还受发布工作与调度影响，没有新变更时由较低频率的强制重发补齐。外部版本、实际间隔及强制重发配置须随每次采样记录，不能把旧版本常数用于当前解释。

“成功回执至选定核验快照生成”统计应按此准确命名。它包含额外连续快照确认及进入发布范围的等待。订单也可能在SDK回执返回前已随快照发布，后续帧计时不会覆盖那次发布；因此即使发布检查为50ms，回执后的下一帧或选定核验帧也不保证在50ms内出现。应同时呈现原生帧间隔、回执后第一帧候选、额外确认与深档子集，不能将候选同价直接等同原订单首次可见，也不能通过相减分位数推导精确延迟。
