# 独立做市管理后台

管理前端和 Hertz/admin、Kratos/operator 位于独立 `hmlax/admin` 项目。管理库只保存用户、商户、菜单权限、审计及商户与做市账户绑定；做市业务库保留策略模板、实例、资金策略和交易记录。operator 使用双向 TLS 调用 strategy 的 `muskdeer.strategy.console.v1.Console`，不连接做市数据库。

## 启用与升级

1. 停止四核心服务并等待租约过期，在备份后运行既有 `instanceupgrade` 维护命令，把独立实例格式从版本 1/2 升到 3。启动只检查迁移账本，不执行 DDL。迁移保留旧账本校验和、资金记录及所有开发成交槽。
2. 为管理 operator 签发同一信任 CA 下、DNS SAN 精确包含 `operator.grpc` 的客户端证书。strategy 使用 `strategy.grpc` 服务证书。
3. 在 strategy 的 Nacos `service.yaml` 的 `grpc_security.allowed_peer_services` 中显式加入 `operator.grpc`。这也是 Console 注册与控制操作的基础设施开关；没有该项则不注册 Console。核心之间现有允许列表和 gRPC 客户端配置保持有效。
4. 管理 operator 的 Nacos 配置保存连接目标、服务名、证书文件引用和超时。环境变量仍只负责连接 Nacos，数据库和应用设置来自 Nacos 双文件。不得把做市数据库 DSN 配给管理 operator。
5. 重启四核心加载完整实例快照。新建或参数修改只保存数据库，要求显式重启加载；不会把 Nacos 或模板参数当作隐式运行默认值。

现有运行服务尚未应用本次迁移、证书或控制入口。

## 行为

- 三种模板只读展示注册实现、数据依赖和参数合同。每个实例保留完整参数及模板修订绑定。
- 创建保存为停止；修改参数要求先停止。`revision` 表示参数版本，`requested_config_version` 表示控制版本，写操作使用两者做乐观并发校验。
- 新建或参数修改后，启动要求策略及三个依赖服务报告已加载该修订。列表同时显示请求运行状态、实际加载版本和待重启状态；该信息不冒充撮合成功证明。
- 停止后策略暂停新增委托；执行保护循环撤销其管理的挂单。停止期间工作器仍保持可恢复的装配，避免把停止误解为永久删除。
- 单独撤单要求停止实例、明确 `cancel_all=true`；仅撤销该实例管理的订单，沿用执行租约、账户门、最终 fencing 及撤单审计。应继续查看撮合原生快照确认结果。
- 原生挂单与持仓来自撮合网关，不使用历史订单审计推断当前状态，不虚构总资产或盈亏。
- WashTrade 仍是开发行情发布，0 次数/累计名义量为不限。暂停不推进序号，恢复不重发已消耗或未知槽。同一品种的未删除开发实例不能复用 run_id。
- 平台允许全局账户；商户必须携带 operator 从管理库查得的非空账户范围。空范围拒绝。开发发布记录按实例归属过滤；无法证明归属的旧记录只对平台可见。
- 配置和控制审计写入已有不可变 `strategy_config_versions`，记录操作人、请求标识、预期版本和期望运行状态。审计参数不是当前运行参数源。
- 不提供实例删除、资金预算修改、真实成交刷量或自动切换行情源。

## 验证

单元与 race 测试覆盖认证/空范围拒绝、参数精度、无限额 0 的保持。隔离 PostgreSQL 回归覆盖账户隔离、并发控制冲突、停止实例装配、运行门禁和完整不可变审计。该回归使用真实数据库，但不发送真实资金委托；管理前后端联调由独立 admin 分支继续完成。
