# MVP 需求规格 v0.1

状态：开发基线草案；2026-10-26。来源：本次 Muskdeer 项目对话。工程约束已由用户指定；现货、自营、网格及阶段范围为可修订的设计默认值，不是用户已确认业务承诺。

## 目标
1. 参考外部交易所行情，在本所提供有真实资金支持的连续双边报价。
2. 使用可配置策略模板交易，追踪参数、订单、成交、持仓及风险。
3. 由 Codex 按可执行验收推进到模拟闭环及真实测试环境接入。

## 默认范围
现货、内部自营；首批 BTC/USDT、ETH/USDT 为模拟样例，可配置但不代表本所实际开通。做市 + 网格两个模板；本所模拟器，以及必须分别实现接入的 Binance、OKX 两家外部行情源。Bitget、Bybit 为后续候选，不计入首批必交付范围。外部交易对冲先模拟后真实适配，其交易所选择独立配置。合约、客户托管策略、任意脚本、生产资金启用不属于默认 MVP。

## 公共模块与服务封装

公共模块名为 deer，所有 Kratos 业务服务分别使用统一的 Deer 封装，由 deer.NewDeer 构造，保留各自服务进程及职责。api 用作平台管理界面，用户已确认包含可操作的管理前端页面和配套后端接口，纳入 MVP。DeerApi 作为 Hertz API 服务封装，配套 deer.NewDeerApi，复用 Deer 的基础设施、注册发现与生命周期；API handler 通过 gRPC 调用业务服务。详细设计见 DEER.md，P02 实现公共封装并通过 A02/A26，P07 实现管理界面并通过 A27。

## 用户流程与可观察行为
### R01 行情
外部行情首批必须对接 Binance、OKX 两家；Bitget（按用户原文 bitgit 规范化命名）、Bybit 为候选。market 按交易所及交易对分别维护连接、订单簿和质量状态，输出含 venue、instrument、event_time、receive_time、sequence、quality、source_version。序列缺口先标 invalid，再重建；无可靠行情不得继续产生风险报价。外部交易对不存在时返回明确错误，禁止悄悄映射其他产品。
### R02 定价与做市
按策略实例所选行情源生成参考价及质量，排除该源的过期、无效和异常行情；不得把未选中的交易所行情混入该实例的参考价。按价差、档位、金额、库存偏移生成目标订单集合；只更新必要订单。每档数量由可用预算、最小金额、精度约束裁剪。不得复制无法承担的外部深度；本所用户订单仍独立存在。
### R03 库存和风控
风险包括持仓、有效挂单、提交中与 UNKNOWN 订单的最坏敞口。单笔/策略/账户/交易对/平台限制均生效；任一硬上限不满足则拒绝新增风险。不同策略必须共享账户额度约束。
### R04 策略实例
创建模板实例，绑定账户、交易对、行情源、代码版本、参数版本和预算。做市、网格等每个策略实例均可独立指定使用 Binance 或 OKX 行情，同一交易对的不同实例可选不同来源。实例可启动、暂停、恢复、停止。重复启动请求幂等。参数校验失败无副作用；修改版本有审计。扩大预算、改变网格范围、切换行情源等敏感修改默认先暂停、撤单确认、再生效；不隐式平仓。
### R05 执行
持久化意图后执行；订单通过正式账户、冻结、撮合链路。超时查询确认，撤单过程中成交仍入账。网关不具备幂等或查询能力时，标接入阻碍，不盲目重试。
### R06 成交和持仓
成交重复消费不重复计账；支持 fee 币种、买卖方向和部分成交。持仓投影按原始成交重建；对账差异可追踪并限制风险，禁止直接篡改核心余额修平差异。
### R07 对冲
以净敞口阈值、最大等待时间、大额立即触发为初始模式；外部账户预置资金。部分成交、未知状态和失败计入敞口，不假定两腿原子。失败积压触发缩量或停止新增风险。
### R08 管理与权限
api 面向平台管理人员，交付可操作的 Web 管理页面和配套管理 API。至少支持以下页面与流程：

- 登录与权限：viewer/operator/admin；菜单、按钮及数据访问与角色一致，后端独立校验每项权限。写操作鉴权、幂等及审计，实盘标志默认关闭，不接受匿名启停。
- 运行概览与行情监控：显示服务/策略运行状态，按来源和交易对显示行情健康、时效及异常原因。
- 策略管理：创建、查询与详情，查看/提交参数版本，独立选择 Binance/OKX 行情源，展示配置来源和实际生效来源；完成启动、暂停、恢复、停止与撤单的管理操作。换源按 R04 的版本与保护流程执行。
- 订单、成交与持仓：提供列表、筛选及业务详情，读取后端真实状态；价格、数量、余额、费用和损益等小数以字符串无损输入、展示及提交，前端不得经 Number/parseFloat 转换。
- 风险与审计：查询风险事件、审计记录与异步操作结果；紧急撤单和风险开关展示作用范围、原因及确认步骤，权限受后端控制。停止、撤单、平仓使用不同操作语义，平仓保持单独受限授权。

页面须处理加载、空数据、参数错误、权限拒绝、版本冲突和依赖故障；202 异步动作展示 operation_id 及最终结果，提交接受状态与业务完成状态分别显示。OpenAPI 文档与管理页面分别交付；浏览器通过实际管理 API 完成上述流程，按 A18/A23/A24/A27 验收。前端技术栈和构建版本在实施时锁定，尚未由用户指定。
### R09 生命周期
多节点接管有租约和 fencing。停止新单、撤单、平仓是三个动作。停止完成仅在挂单终态/明确异常处理后返回；单纯停止进程不代表撤单成功。
各业务服务通过 Deer 统一管理 Kratos 启停、就绪与资源清理；DeerApi 将 Hertz 纳入同一生命周期，初始化失败清理已创建资源，正常停止等待在途请求后清理依赖。

## 外部行情源与实例配置

| 行情源 | 统一标识 | 交付范围 |
|---|---|---|
| Binance | binance | 首批必须接入 |
| OKX | okx | 首批必须接入 |
| Bitget | bitget | 后续候选，用户原文 bitgit 按此理解 |
| Bybit | bybit | 后续候选 |

- 策略实例通过公共配置字段 market_data_source 指定一家行情源，首版支持 binance、okx；该字段适用于所有策略模板，写入配置版本并在创建、详情和配置查询接口返回。候选源在适配及验收完成前不可作为可用源启用。
- 首版采用每实例单源选择；原 source_set 泛化参数统一调整为 market_data_source。多源聚合、权重及自动主备切换不作为本次要求的默认行为。创建或更新配置时明确所选来源，禁止依赖进程全局默认值覆盖实例配置。
- 启动或恢复前检查所选源已启用、支持对应交易对，且快照完整、数据新鲜；未知标识、未接入候选或不支持的交易对返回明确错误。配置可保存，但源不健康时不得进入可报价状态。
- 所选源断连、过期或序列失效时，停止该实例新增报价并按既有保护流程撤旧单；其他来源健康不能触发隐式换源。其他实例按各自来源与健康状态独立运行。
- 切换来源通过新配置版本及审计完成：暂停新增报价、撤旧单确认，等待新来源完整且健康的行情，再按新配置恢复。丢弃旧来源及旧配置版本的积压行情；重启或节点接管后恢复同一已生效选择。
- 行情选择只决定数据输入，不自动变更本所下单、外部对冲场所或账户；这些配置分别管理。

## 做市参数
symbol、market_data_source、quote_levels、level_spacing_bps、base_spread_bps、level_notional、side_budget、inventory_target、inventory_soft_limit、inventory_hard_limit、reprice_bps、min_refresh_interval、max_quote_age、max_market_age、hedge_threshold、hedge_max_wait、max_hedge_backlog。
参数均有类型、单位、边界、交叉校验和生效方式；所有小数参数及接口字段均为十进制 string，覆盖数量、金额、价格、费率、比例、百分比等，Go 中统一用 decimal.Decimal 存储和计算，禁止浮点中转；时间必须有明确单位。样例参数仅供模拟，不作为生产推荐。

## 网格参数
market_data_source、lower_price、upper_price、grid_count、total_budget、per_order_notional、inventory_limit。明确初始持仓要求、越界暂停策略、成交后补单规则及部分成交策略。禁止把价格触达当成完全成交。

## 性能与容量
P01 记录目标交易对数、档数、更新频率和部署硬件；P10 给出实测 p50/p95/p99。未提供的延迟/容量目标不得编造为 SLA。模拟健康场景报价至少连续运行 30 分钟，无未解释订单或持仓差异；故障触发和恢复时间按测试配置断言。

## 完成层级
L1：模拟系统端到端及故障验收通过。L2：真实本所及外部测试环境对接通过。L3：生产发布另行授权。L1 不得宣称 L2/L3 完成。
