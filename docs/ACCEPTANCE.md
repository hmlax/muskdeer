# MVP 验收矩阵

本表是待实施测试，不是已通过报告。每条记录环境、版本、命令、输出位置、结果、限制；失败或未运行如实标注。故障通过注入器和受控时钟触发，避免随机 sleep。L1 使用隔离模拟器，L2 针对真实测试环境重新验证。
Go 版本固定为 1.27.3；代码生成、构建及测试报告记录实际 go version，doctor/CI 校验 go1.27.3。其他编译器版本的结果不能代替本项目固定版本的验收证据。

## 公共服务封装验收细则

- A26 检查 market、strategy、execution、portfolio、cron 均通过 deer.NewDeer 构造服务，API 通过 deer.NewDeerApi 构造 DeerApi；服务身份、端口、注册及状态各自独立，实例间不能共用进程全局运行状态。
- 验证 DeerApi 在 API 进程中复用一个 Deer，公共连接及日志等依赖只初始化一次；Hertz 与业务 gRPC 调用可用，readiness 能反映必需依赖状态。
- 正常停止时 Hertz 停止接收请求并处理在途请求，Kratos、gRPC、注册发现和依赖按约定关闭；重复 cleanup 不重复释放。部分构造失败行为按 A02 额外验证。

## 行情源与选择验收细则

- A24 对做市和网格模板分别覆盖创建、更新与查询来源；同一交易对设置一个 binance 实例和一个 okx 实例，注入明显不同的价格及序列，断言各自参考价和订单目标只受所选来源影响。
- 仅使 Binance 断连/过期，验证选 binance 的实例进入保护、撤旧单且不偷偷改用 OKX，选 okx 的健康实例继续按自身配置运行；反向场景同样覆盖。
- 切换来源需校验 expected_version 并记录前后来源；新源完整健康之前不恢复报价，旧源/旧版本排队数据不得驱动新报价。重启及 owner 接管恢复同一生效配置。
- 未知标识、未接入的 bitget/bybit、不支持的交易对须明确拒绝；所选源尚未就绪不能报价。接口返回配置来源和实际生效来源，不能只验证保存字段。
- A25 为 Binance、OKX 分别记录环境、时间、实际交易对、订阅和恢复证据，真实网络不可用时标未通过/未运行并保留原因；可在 P05 执行，不能因此将真实下单或完整 L2 交易验收标为完成。

## 数据库规范验收细则

- A01 检查每张表的真实数据库元数据及生成模型：主键、自增、NOT NULL/nullable 均正确；不能只看 Proto 或 GORM tag。
- 不传 Id 连续插入两条记录，确认数据库分配不同主键；不要求序列无间断。验证 createAt/updateAt 插入时有值、更新后 updateAt 生效且 createAt 不变；数据库拒绝两个必填时间列的显式 NULL。
- deleteAt 初始为 SQL NULL，写入删除时间后可准确读回；如采用软删除，验证默认查询过滤。自然键去重和幂等验收仍须通过，不能因增加 Id 而丢失唯一约束。
- A22 对全部 Go 源码（含生成模板、脚本与测试）进行静态检查及审查，排除字符串选表和封装绕过；只搜索 db.Table 不足以覆盖 tx、其他变量及跨行链式调用。静态检查纳入 verify/CI。

## 小数规范验收细则

- A23 检查 Proto/OpenAPI 及实际请求、响应、WebSocket、事件与嵌套字段：全部小数字段为 string，JSON 实际输出带引号，禁止 float/double/number 类型声明；配置和模拟器的小数输入同样检查。
- 验证 "0.1" + "0.2" 按约定输出 "0.3"，以及超过 float64 精度的有效位、最大小数位、负数、零、空值和 PostgreSQL numeric 往返；测试值从字符串构造 decimal，不经浮点初始化。
- 非法格式、NaN/Inf、未约定的科学记数法及超出精度/范围的输入被明确拒绝；请求的小数字段传 JSON number 时不能静默接受并转为浮点。缺失、NULL 与零按字段契约区分。
- 除法与价格/数量量化覆盖边界舍入；实际输出遵守字段规定的位数和格式。静态检查及审查覆盖 float32/float64、浮点初始化与封装转换，确认 Go 小数计算和比较使用统一 decimal 库；纳入 verify/CI。
