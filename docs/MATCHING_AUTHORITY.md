# 当前通道以撮合为准

2026-11-09 用户明确取消当前通道运行的数据库进程执行权记录，以及本地历史资金预留汇总。本约定替代旧文档中要求当前实例续租、最终执行 epoch 和累计未知资金预留的部分。

四核心通过 `strategy_instances` 装配时：

- market 不取得、续期或查询行情发布租约。行情的 source、segment、symbol 及观察时间仍校验，数据过期即不可用。
- strategy 不记录执行者及有效期，通过已有认证的 gRPC 服务路由访问 execution，不按数据库所有者选节点。
- execution 不取得基金或开发成交租约。新下单/撤单审计的 owner 为空、epoch 为零；新订单 reserved_notional 为零，不增减账户历史 reserved_notional，也不按旧订单状态求和。
- portfolio 保存可重建的撮合观察，不再记录发布进程。管理后台撤单同样不依赖历史租约。

资金判断使用当前撮合挂单、持仓、可用资金观察和已有单笔/总名义金额参数。观察后尚未反馈的请求不再另建本地累计预留，撮合侧资金冻结及拒单为权威；多个未反馈请求不能再声称由本地累计预留覆盖。一次报价循环中的网格风险计算仍包含该循环已经发送的目标。

实例修订、模板/品种启用状态、启停、商户权限、源数据新鲜度、请求截止时间、持久化请求身份和单次发送保持。最终发送仍检查当前实例配置；这里锁定的是配置记录，未写进程所有者、租约到期或权限令牌。同一请求从 PREPARED 一次性进入 DISPATCHED 后不会因丢失回执重发。撤单依当前撮合订单 ID 发起，每个撤单意图单次发送。

开发 WashTrade 仍为 development_only 合成行情，零次数/名义量上限仍表示不限制，原批次和已消耗序号不重置。原有完整历史槽校验保留；并发槽领取在现有实例记录的短事务和唯一键上串行化，UNKNOWN 槽仍消耗并返回原结果，不再次发布。没有添加真实账户对刷。

取消进程所有权后，不再保证跨副本独占执行，也没有把相同授权转存 Redis 或依赖 Nacos 在线状态。当前本地部署每个核心服务一个进程；每个进程按实际配置装配全部实例，无固定实例容量限制。同一业务请求的持久化去重不等于多个独立进程分别生成的新请求也能去重。

显式格式版本5只调整新记录约束，解除当前账户/撤单对历史租约行的外键依赖；已有表、历史 owner/epoch、订单状态、历史预留和开发槽均保留，不清零。版本1–4的迁移字节和账本原字段不改。历史恢复/旧模拟回归接口保留原合同，但四核心当前实例入口不使用它们。

升级必须先停止当前四核心并备份，再离线执行 instanceupgrade，最后配套更新四核心镜像。旧租约过期是旧版本退出的附加检查；版本5部署后，不能把“没有有效数据库租约”当作进程已停止的证据。启动只校验完整账本，不自动迁移。历史审计中的预留列不再表示当前实际冻结资金。
