# 成交与持仓投影

P04.4 提供直接仓储消费者和重建路径，事件发布/拉取消费及业务 RPC 在后续接入。模拟核心资金和成交是权威；PortfolioAccount、PortfolioFill 与 ConsumerInbox 是可重建投影及消费记录。

## 起点和计算

每个初期模拟账户绑定一个交易对，提供显式 opening quantity、quote cash、quote cost。初始化只允许尚无核心成交的账户，并核对 available+frozen 总资产；不从之后的市场价格猜历史成本。起点字段由数据库禁止修改，重复初始化不能覆盖已存在的起点。其他交易对使用独立账户。

买入的 quote notional+fee 增加成本、减少现金，增加 base 数量；卖出从 quote 收入扣费，按平均成本计算已实现损益。移除成本以36位小数向零截取，最后一笔清仓移除全部剩余成本，避免留下舍入尾差。所有计算使用 decimal，账本/投影 numeric(76,36)，单笔价格/数量仍限制20位整数/18位小数。费用当前只支持 quote 币种。

## 事件与去重

eventwire.Fill 验证版本、producer、单一 typed payload、来源序列、方向及严格十进制字符串，并以确定性 Proto 字节计算 inbox 指纹。JSON number、科学记数法、NaN、错误金额乘积、混合 payload 和未知版本均拒绝。事件 aggregate ID 为源成交游标，aggregate version=1；它与订单/撤单聚合分别通过类型区分。

消费在同一事务保存 consumer+event_id inbox、venue+trade_id 自然键事实和投影。相同 event ID 内容改变拒绝；不同 event ID 重复同一真实成交不重复计账。消息处理提交后才能 ACK，不能先确认再更新投影。

L1 消费者核对事件与真实模拟核心不可变成交、订单和 OMS 身份；同时比较当前核心成交数量及最新游标，确认来源集合完整。游标不假定连续，其他账户和回滚可以产生间隔。尚缺事实时保存已验证消息与事实，保留最后完整投影并标 SOURCE_INCOMPLETE，不制造余额或跳过交易。完整事实按源游标排序后从起点重算，因此交付顺序不改变成本及费用。

## 对账与恢复

重算结果与模拟核心 available+frozen 总资产比较；差异标 RECONCILIATION_MISMATCH 并关闭风险输入。不会修改核心余额来修平差异。读取也检查源游标和实际资产，发现损坏或新事实时不继续声明已对账。显式 Rebuild 从不可变事实恢复投影。

投影重建最多处理每账户10000笔事实，超限保持不完整并关闭风险；这是初期实现的容量边界，后续性能结果以 P10 实测为准。当前数据核验依赖 L1 的共享模拟数据库，真实交易源的游标/完整性与对账合同仍须 P11 验证。

投影完成只标记自身对账状态，不自动重新授权 RiskSnapshot。后续风险生产者须基于新持仓、当前限额和所选来源行情重新决策，不能通过刷新时间戳绕过风控。
