# 风险快照诊断变更历史

P07.47新增[RiskSnapshotEvent Proto模型](../deer/proto/model/v1/risk_event.proto)与[版本31迁移](../internal/migrate/sql/0031_risk_snapshot_events.sql)，为后续管理风险事件查询提供真实持久来源。此步尚无RPC、HTTP或页面，不把当前快照拼成未曾保存的过去。

## 记录含义

风险快照依然是实际准入链路中的原有输入；历史记录是诊断事实，不是当前许可。记录中的allow_new_risk/reconciled、原因、配置/来源/发布者代次及观察/截止时间，只反映该次写入值。实际订单仍逐次检查当前预算/对账/新鲜所选行情、全部所有权和最终fencing。

[记录类型](../internal/domain/risk_events.go)仅有：

- BASELINE：首次保存某快照或启用历史记录时的现有值，是可用记录起点，不声称曾发生某个过去的状态变化。
- CHANGED：策略/账户/交易对/配置、来源/绑定/发布者代次/政策，或原始许可位/对账位/原因/退役状态实际变化。
- REMOVED：源快照被物理移除，保留最后可见原始值和snapshot_deleted=true；逻辑退役则为CHANGED并保留退役标志。

普通行情序列/发布修订、快照修订、观察与有效期刷新不单独写历史；有效期自然流逝也不会虚构一条源数据库未发生的事件。若生产者之后明确写入失效原因，按实际变化记录。快照源修订可以跳号，且不是历史事件的唯一身份；查询及后续交付必须使用独立事件自增ID，不能用源修订冒充去重键。

例如核心成交先提交、持仓尚未投递时，现有链路在同一事务将reconciled置false；allow_new_risk和reason_code可能仍保留旧值。历史如实记录这种组合，不改写成READY许可或自动修正原因。准入检查仍因当前对账位失效拒绝新增风险。

## 原子性与迁移

PostgreSQL源表AFTER触发器在快照INSERT/UPDATE/DELETE的同一事务写历史，覆盖现有生产者、核心成交失效和管理端重置路径，不新增轮询器、订阅者、goroutine或连接。源事务失败时历史也回滚；历史写入失败同样不能留下一个没有对应历史的已提交源效果。核心成交路径的资金、订单、成交/outbox及风险变更继续沿原事务处理，未新增重试或绕过最终fencing。

事件表有统一四公共字段、自增主键、按策略/账户/源快照和事件ID的索引，以及与策略账户/历史配置一致的外键。源快照ID是历史引用而非阻止源移除的外键；历史不随源行删除。所有历史字段、公共更新时间和delete_at均不可改写/删除，delete_at列可空且记录始终保持NULL。

迁移在原校验和/事务锁机制内，短暂锁定源表写入，串行化记录起点与启用捕获，避免两者之间出现缺口。已有活动及退役快照只补一条BASELINE，保留原源字段与高位ID/序列/修订，不改源快照或任何资金；重复执行已应用迁移不重复补记录。服务启动只CheckCurrent，不执行迁移。

这是内部快照诊断历史，不替代管理操作的[权限审计与操作收据](ADMIN_RISK.md)，也没有新增JetStream发布或业务恰好一次声明。后续管理读取仍须当前viewer、明确范围、只读快照和原始字段校验；不能从历史“恢复风险”。
