# 风险快照诊断变更历史

P07.47新增[RiskSnapshotEvent Proto模型](../deer/proto/model/v1/risk_event.proto)与[版本31迁移](../internal/migrate/sql/0031_risk_snapshot_events.sql)，为后续管理风险事件查询提供真实持久来源。P07.48增加只读管理查询仓储；P07.49接入typed gRPC/HTTP；P07.50交付风险历史页面，不把当前快照拼成未曾保存的过去。

## 记录含义

风险快照依然是实际准入链路中的原有输入；历史记录是诊断事实，不是当前许可。记录中的allow_new_risk/reconciled、原因、配置/来源/发布者代次及观察/截止时间，只反映该次写入值。实际订单仍逐次检查当前预算/对账/新鲜所选行情、全部所有权和最终fencing。

[记录类型](../internal/domain/risk_events.go)仅有：

- BASELINE：首次保存某快照或启用历史记录时的现有值，是可用记录起点，不声称曾发生某个过去的状态变化。
- CHANGED：策略/账户/交易对/配置、来源/绑定/发布者代次/政策，或原始许可位/对账位/原因/退役状态实际变化。
- REMOVED：源快照被物理移除，保留最后可见原始值和snapshot_deleted=true；逻辑退役则为CHANGED并保留退役标志。

普通行情序列/发布修订、快照修订、观察与有效期刷新不单独写历史；有效期自然流逝也不会虚构一条源数据库未发生的事件。若生产者之后明确写入失效原因，按实际变化记录。快照源修订可以跳号，且不是历史事件的唯一身份；查询及后续交付必须使用独立事件自增ID，不能用源修订冒充去重键。

例如核心成交先提交、持仓尚未投递时，现有链路在同一事务将reconciled置false；allow_new_risk和reason_code可能仍保留旧值。历史如实记录这种组合，不改写成READY许可或自动修正原因。准入检查仍因当前对账位失效拒绝新增风险。

## 原子性与迁移

PostgreSQL源表AFTER触发器在快照INSERT/UPDATE/DELETE的同一事务写历史，覆盖现有生产者、核心成交失效和管理端重置路径，不新增轮询器、订阅者、goroutine或连接。源事务失败时历史也回滚；历史写入失败同样不能留下一个没有对应历史的已提交源效果。核心成交路径的资金、订单、成交/outbox及风险变更继续沿原事务处理，未新增重试或绕过最终fencing。

事件表有统一四公共字段、自增主键、按策略/账户/源快照和事件ID的索引，以及与策略账户/历史配置一致的外键。源快照ID是历史引用而非阻止源移除的外键；历史不随源行删除。所有历史字段、公共更新时间和delete_at均不可改写/删除，delete_at列可空且记录始终保持NULL。

迁移在原校验和/事务锁机制内，短暂锁定源表写入，串行化记录起点与启用捕获，避免两者之间出现缺口。已有活动及退役快照只补一条BASELINE，保留原源字段与高位ID/序列/修订，不改源快照或任何资金；重复执行已应用迁移不重复补记录。服务启动只CheckCurrent，不执行迁移。

这是内部快照诊断历史，不替代管理操作的[权限审计与操作收据](ADMIN_RISK.md)，也没有新增JetStream发布或业务恰好一次声明。后续管理读取仍须当前viewer、明确范围、只读快照和原始字段校验；不能从历史“恢复风险”。

## 只读管理查询

P07.48的[AdminRiskEvents](../internal/domain/admin_risk_events.go)复用当前viewer及以上角色鉴权，在同一PostgreSQL只读Repeatable Read事务中提供列表/详情。列表可按策略ID、业务账户、交易对ID、Binance/OKX来源、记录类型与八种已定义原因精确组合筛选；页长1–100、事件ID升序及after_id游标。过滤值缺席表示不限，未知历史范围返回空页；详情身份不存在为not found。历史范围不要求当前快照、活动策略、核心账户或行情绑定存在，不把已退役记录隐藏在当前目录后面。

结果直接保留事件ID、记录时间、源快照ID/修订、配置/来源/可空绑定、发布者代次/序列/修订/政策、观察与截止时间，以及明确命名的RecordedReconciled/RecordedAllowNewRisk、原原因和源退役标志。过期记录仍可阅读；不会与当前时间比较后改写为新的风险事件，不依据旧READY/许可位授予交易权限。可空绑定保持缺席，所有身份/版本保持int64精度；读取对象不共享生成模型的可变指针。

查询只读已保存历史，不调用RiskEvaluator或Portfolio Get/Rebuild，不取得租约、初始化资金、更新源风险位或释放预留。非法持久字段、数据库错误或取消整页失败，不返回部分记录/游标；私有数据库原因保留在内部错误链，公开文本为固定安全错误。每次读取均验证当前会话；真实Logout撤销后拒绝列表及详情。

分页用于交互式历史浏览，不是持久消息投递游标；独立事务可能按不同顺序分配和提交自增ID，刷新查询才重新观察当前完整可见范围，不据此声称业务恰好一次或历史完整对账。

## typed gRPC与HTTP

P07.49提供[StrategyRiskEventQuery](../api/strategy/v1/risk_events.proto)的ListRiskEvents/GetRiskEvent及具体RiskDiagnosticEvent。仅在strategy的management_enabled时注册，要求已验证API服务身份、当前viewer会话、最大5秒调用和2KiB请求；读取节点不注册控制写RPC。API在strategy_queries_enabled下使用既有唯一strategy连接，不启动事件生产者、投影消费或其他工作器。

Hertz只读入口：

- `GET /api/v1/risk-events`：可选`strategy_id`、`account_id`、`instrument_id`、`market_data_source`、`kind`、`reason_code`及`after_id`、`limit`。
- `GET /api/v1/risk-events/:eventID`：精确记录详情，不接受查询参数或请求体。

策略/产品/记录身份为规范正十进制int64；页长默认20、上限100，after_id可为0。未知、重复、空筛选、非法枚举、非规范ID、超1024字节查询或GET请求体为400；无会话401、权限拒绝403、详情不存在404、依赖或非法成功数据503。历史范围没有记录返回200空列表，不能据此判断当前资源存在。请求有三秒预算，响应no-store；全字段检查记录/分页/过滤及详情身份绑定，任何错误拒绝整页业务数据。

JSON沿标准ProtoJSON输出，所有int64身份、修订、序列、时长与毫秒时间均为string；可空market_feed_id缺席时省略，不制造0或null标量。记录许可位和对账位仍为bool，旧READY/已过期记录按原样传输。所有权、会话、请求键和内部错误均不作为事件业务字段返回。风险历史没有写入口或从旧记录恢复许可的能力。

## 风险历史页面

P07.50提供`/risk-events`列表及`/risk-events/:eventID`独立详情、查询导航和策略详情入口。viewer/operator/admin共用当前后端查询权限；风险历史没有写按钮。六种精确筛选显式应用，1/20/50条分页，筛选及页长写URL并支持刷新，详情支持未登录深链接恢复。源移除或策略退役不隐藏历史，未知历史范围显示空页，详情不存在明确提示。

页面分别展示记录起点/诊断变化/源移除、记录时间与源快照/配置/来源，记录许可位/对账位/原因和观察/截止时间，以及当时的行情引用。旧READY显示“曾判为就绪”，保留true/false原文与“历史诊断/不授予当前风险”提示。无绑定显示“未记录”，高位身份/序列仍为string/BigInt；超出安全日期范围按原数字显示，不做风险时效判断。

六秒取消、错误清空旧数据、401回登录，读取不自动轮询、不存储业务数据或恢复许可。1440/800/390宽度及高位字符串截图验证无整页溢出；导航按完整链接换行。第13组`make admin-risk-events-browser`已接CI/e2e，真实浏览器验证与范围见[P07.50](validation/P07-50.md)。
