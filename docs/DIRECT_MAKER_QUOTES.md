# 做市铺单订单不落库

实际报价的源序列、目标和原SDK订单身份通过只读诊断流关联；它不是订单账本，也不把成功回执当成盘口可见。合同、临时队列边界和可证实可见上界的统计方法见[报价链路耗时](QUOTE_LATENCY.md)。

2026-11-24 用户要求当前做市铺单移除PostOnly：首次下单、补单和替换单的SubmitQuote统一使用SDK LIMIT + GTC。数量、价格与有效期检查继续按原策略执行，限价可成交时允许撮合，未成交数量继续挂单。只改变当前直发铺单的订单类型；持久下单路径的历史请求摘要及其他策略合同保持，不重写旧订单或批量撤销切换。

2026-11-09 用户进一步明确：当前 market_maker 铺单的订单数据不需要数据库。这替代先前“仍记录意图、确认回执和撤单”的约定。

当前实例的链路为：读取数据库策略/品种/账户配置和启停，取得新鲜行情与撮合账户观察，直接调用 SDK 的普通限价单 LIMIT + GTC 下单或按撮合订单 ID 撤单。请求只携带撮合需要的业务作用域、client_id、方向、价格、数量及杠杆，不伪造本地 intent_id、owner 或 epoch。下单与撤单均不会进入本地 Prepare/claim/Acknowledge 或撤单日志事务。

execution 的铺单路径不读写 venue_order_intents、venue_cancellations，不执行本地订单观察、恢复扫描或资金观察更新。portfolio 对包含铺单的账户只在内存保存短期快照；不会把挂单藏入 venue_account_snapshots 的 JSONB。快照由撮合持续刷新，过期或作用域不符就拒绝读取，调用方得到独立副本；进程重启从撮合重建，不回退旧数据库快照。

实例启停/修订、模板/品种启用及账户配置在发送前只读检查；不建立或持有订单事务。资金上限使用最新撮合挂单、持仓、可用资金和当前循环已发送目标计算。现有价格/数量规则、单笔与总预算、新鲜度、有界请求及服务鉴权保持。取消旧报价的首次切换状态在内存维护，不为订单写运行状态。

SDK 不自动重试下单；超时返回未知结果，后续按撮合当前挂单重新计算，不重发原请求。取消本地订单日志后，不再宣称本地具备跨进程重启的持久发送去重；撮合订单和 client_id 为查询依据。没有把本地订单记录转存 Redis、消息队列或其他数据库。

本次不清空旧订单、撤单及快照，不改变迁移账本，不改模板、实例参数、控制版本或最终启停。网格仍用已有下单记录；development_only 合成成交保留原批次、消耗序号和去重。商户实时挂单继续从撮合观察读取，本地订单/撤单历史查询仅表示保留的旧记录。

验收同时检查 SDK 实际收到新挂单/撤单，以及本地订单、撤单和快照表完全不再增长或更新；不能只验证删除某一行数据库调用。

## 行情推送驱动的目标计算

2026-11-28 用户要求铺单策略由行情推送驱动，以缩短第三方行情到我方盘口的时间。当前 market_maker 实例（instance_id>0、非网格/长网格）的 strategy 工作器订阅 market `SubscribeBooks`，每收到更新的源序列就立即用这一帧计算目标并调用 execution Reconcile；不再等待 PollInterval 相位，也不在该帧之后串行查询数据库或 portfolio。订阅只保留一帧待处理，旧帧被新帧替换；更旧、重复或已过期的帧不提案。

实例启停、当前账户政策与 portfolio 规则观察由同一工作器内的独立读取者按原 PollInterval 刷新为不可变副本。每份观察只在其读取开始后 PollInterval+OperationTimeout 内可用；读取失败立即撤回、实例停止或观察过期时不提案，因此停止生效延迟与原轮询同级。连续一个 PollInterval 没有任何提案时，工作器回退为原 GetBook 读取并提案；订阅断开时按原间隔重连，期间由该回退继续报价。

该副本不授权任何发送：execution 接收目标时仍校验实例/模板/品种/预算，写入者仍读取新鲜撮合账户，并在每笔发送前独立检查配置与预算。价格/数量规则、源新鲜度、单一写入者、最新目标邮箱、SDK 不重发及 UNKNOWN 处理不变。网格、长网格、旧非实例路径和 WashTrade 不改。提案频率随源帧（当前 depth20@100ms 加 REST 兜底）变化，Reconcile 次数可能高于原 200ms 轮询；邮箱合并保证不会在 execution 积压旧目标。

## 轮次内预算与每波配置读取

2026-11-28 用户要求继续优化 execution 发单前耗时。当前铺单写入者在一轮内持有基金写入门控期间读取一次账户政策（启用、总/单笔名义额、杠杆等），该轮每个候选订单的预算检查复用这份读取；账户政策修改和账户停用都经过同一门控串行，因此一轮内该行不会被运行中的管理操作改变。每个候选仍把同轮所有已接纳兄弟订单计入总额，最新撮合挂单、持仓和可用资金仍来自本轮新鲜观察。

实例停止不经过基金门控，所以当前配置（实例启停/修订、模板启用、品种交易状态）仍在每个发送波次派发前重新读取，只是同波最多8笔共用这一次读取；拒绝时整波不发送。单独发送路径仍逐笔读取。取消后被接纳的兄弟请求不会进入 SDK。SDK 账户读取顺序（账户先于挂单、挂单先于持仓）保持不变。

## 最新目标与单一写入者

当前做市 Reconcile 在鉴权、实例/模板/品种及预算启用、所选源和目标参数检查后，接收一份完整的具体目标。每个实例只保留最新一份不可变副本，更新不会在 SDK 回执后排队累积；倒退的源观察不覆盖较新的目标。返回 RECOVERING 且计数为零只表示已接受待执行目标，不代表 SDK 已成功下单。

strategy当前做市工作器从首次新鲜、正确作用域的portfolio观察中复制品种刻度、数量/名义额限制和最大杠杆；随后portfolio返回Unavailable时，可使用这份规则和新的所选源生成价格目标。这里只保存规则与作用域，不保存资金、持仓、订单、市场价格、费率或账户有效期，不把规则副本当作资金授权。冷启动、权限/取消错误、过期行情及作用域不符仍拒绝，网格/历史路径保持原库存输入要求。execution在真正发送前继续独立读取新鲜撮合账户并执行所有资金和配置检查。

既有生命周期工作器在同一基金独占写通道内读取新鲜撮合状态、重新检查预算与配置并执行先补后撤。每次操作仍受原行情/账户有效期及配置请求期限限制，过期目标只进入风险保护；没有延长旧观察、并行基金写入或重试原 SDK 请求。停用和停止取消所有者并等待已发调用退出；实际挂单与结果从撮合观察读取。最新目标邮箱不保存订单、回执或资金账本，不写数据库或 Redis。

账户观察返回后，写入者检查邮箱是否已经接收更新且仍有效的目标，并重新读取当前所选源、校验目标身份后再计算挂单及撤单。账户观察的原请求时间和有效期保持，所有发送继续受其剩余期限限制。失败仍执行原保护，下一轮从最新目标开始，不在同一轮重复计算已经使用的目标。

若等待账户观察时原源帧或目标已经过期，而且没有更新有效目标，不再执行普通退旧；原保护流程重新判断当前所选源和账户，不能按过期目标直接选择整侧撤单。

每批补单全部返回后，如果邮箱内已接受更新且新鲜的买一/卖一价格，停止旧目标的后续深档，完成已发送批次的普通观察；若退旧前或两批撤单之间该更新仍新鲜，废弃旧目标尚未发送的撤单选择，交回同一写入者处理最新目标。账户观察过期，或当前自有挂单按新目标已经不安全时，仍返回错误并执行原保护，不能靠交接延长观察或保留不安全报价。只有价格或侧存在性变化会触发交接；数量变化和相同价格的小数格式变化继续补深度。已经发送的SDK调用全部加入，原有效期与风险保护不变。

预先选定的做市撤单每批最多四笔，与补单共用进程内最多十六个在途传输位置；每批全部返回后才能进入下一批或释放基金写通道。部分失败停止后续批次，不透明重发。撤单集合仍按全部成功的最坏情况保护可见替代单和安全档数；网格及历史路径继续串行。

当前实例在读取行情、账户和创建SDK请求前，由已有生命周期工作器按FIFO取得轮次准入。等待项只是该工作器的执行机会，每个实例仍只有一个最新目标邮箱；等待受原操作时长约束，取消移除等待并归还已授予容量。取得准入后才读取邮箱最新目标、启动原操作期限并读取新鲜观察，不改变旧目标的有效期，也不延长已经发出的RPC。

初始观察准备和真实SDK发送容量使用独立的公平预算。账户观察返回即归还准备名额，包括读取失败；后续目标计算、配置/预算检查和未发单尝试不继续占用。串行SDK准入也在等待前归还准备名额，不能覆盖保护撤单；首个波次及整轮结束的重复归还保持幂等。账户/行情读取及波次后的重新观察不保留发送位置；只有即将执行的SDK波次取得一个真实位置，并在没有等待的发送者时借用额外空闲位置。发送波次排队仍受原行情、账户、执行期限及500ms SDK预留限制，过期不发送。每波最多4笔、当前铺单通道共享最多16个真实SDK写入；每个实际并发子波次全部加入后立即归还发送位置；拥塞时若只取得一个位置，不持有该位置串行执行整组，而是归还后重新按FIFO排队。失败停止未发送的后续部分，不重发未知请求。单独记录轮次等待和wave.admission等待，不能把等待移动到其他阶段后误报为已经消失。

失败保护继续读取当前账户政策、实例启停和当前所选行情。账户观察只在同一执行尝试内复用，并校验原作用域、tick/step及原有效期；不跨轮次共享，不延长2秒账户观察有效期。SDK下单或撤单开始前就使该观察失效，包括之后得到未知结果的调用；后续保护因此必须读取新观察。有效且未经过SDK写入尝试的本轮观察可以用于风险减少，不再重复四项SDK查询。当前铺单的受控撤单完成后不再做无人使用的额外账户查询；回执不被当作撤单终态或资金释放证明，后续轮次仍从撮合重读。历史/网格路径及所有原资金和新鲜度校验保持。

满档、安全且本实例目标最优价已可见时，非紧急维护发单还须取得全进程共享的四个非阻塞名额之一，繁忙则留待后续新鲜观察。它们仍计入原十六个传输位置；缺少安全深度或请求正在补缺失的目标最优价时，直接使用原全局位置。最优价只按本实例可见有效订单判断，数量变化和其他账户同价单不会冒充这一条件；所有已发调用结束后归还名额，实例数量、业务参数和最终资金检查不变。

浅侧如果已有稳定、自有、安全且处于目标外沿或更远的可见挂单，外沿保底已存在，补单先发缺失的最优价，再补其他档位；不再先占用SDK名额重复铺外沿。没有外沿覆盖的浅侧仍先铺外沿再补最优价，空侧保护保持。超额、数量已耗尽、其他实例、仅发出未见单和待撤订单都不能提供该覆盖；已有原深单的金融占用仍计入完整风险观察。浅侧深度优先和对侧最优价的波次分配、容量、有效期、数量与资金限制保持。

当一侧已占满目标档数与过桥容量且有不安全旧单，或新鲜SDK观察仍显示已发撤单的挂单时，先撤每侧最多两笔对应自有订单，再重新读取撮合；只有实际观察释放的位置可用于补单。安全替代单可见后再撤余下旧单，避免容量已满时无法补单却直接清空整侧。目标、容量、资金限制及新鲜度不变，最后一笔稳定订单不作为这一步的腾位候选；已发撤单继续活动不会冻结整个账户，也不能作为撤掉最后稳定挂单的依据；失败仍执行原风险保护。

过桥容量被安全旧单占满时，持续更新的源价可能反复推迟普通退旧，导致更近的目标买卖一始终没有位置。只有目标最优价能改善本实例当前最优价、且同侧尚未选择上述不安全/待确认撤单时，每侧最多另外选择一笔最远的自有安全旧单或重复单腾位。当前最优价格继续可见；唯一安全档数不低于目标档数，原已不足目标档数时不再减少其唯一档数。目标内唯一档位、其他实例订单和待确认撤单不作为这一步的新候选；已有同价或更优价时不为数量刷新执行此腾位。仍先重新读取撮合，回执本身不释放容量或风险；源/账户过期仍不发送新报价，不扩大过桥位或任何资金参数。

SDK撤单所有者可能在调用超时后继续完成。进程内仅保留已经发送撤单的订单ID及返回时间作为深度提示，不记录本地订单状态或回执；这些订单不计作稳定替代深度或已保留的目标最优价，也不能支持继续撤掉同侧最后的稳定挂单。完整SDK快照仍用于容量、交叉和资金计算，ACK或超时都不释放占用。只有开始时间晚于该提示、仍新鲜的SDK观察确认订单不再活动时，才清除提示；旧观察和同毫秒观察不能清除。已知未发出的撤单不产生提示，风险减少与停用撤单保持原行为。
