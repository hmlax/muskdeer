# 做市铺单订单不落库

2026-11-09 用户进一步明确：当前 market_maker 铺单的订单数据不需要数据库。这替代先前“仍记录意图、确认回执和撤单”的约定。

当前实例的链路为：读取数据库策略/品种/账户配置和启停，取得新鲜行情与撮合账户观察，直接调用 SDK 的 POST_ONLY 下单或按撮合订单 ID 撤单。请求只携带撮合需要的业务作用域、client_id、方向、价格、数量及杠杆，不伪造本地 intent_id、owner 或 epoch。下单与撤单均不会进入本地 Prepare/claim/Acknowledge 或撤单日志事务。

execution 的铺单路径不读写 venue_order_intents、venue_cancellations，不执行本地订单观察、恢复扫描或资金观察更新。portfolio 对包含铺单的账户只在内存保存短期快照；不会把挂单藏入 venue_account_snapshots 的 JSONB。快照由撮合持续刷新，过期或作用域不符就拒绝读取，调用方得到独立副本；进程重启从撮合重建，不回退旧数据库快照。

实例启停/修订、模板/品种启用及账户配置在发送前只读检查；不建立或持有订单事务。资金上限使用最新撮合挂单、持仓、可用资金和当前循环已发送目标计算。现有价格/数量规则、单笔与总预算、新鲜度、有界请求及服务鉴权保持。取消旧报价的首次切换状态在内存维护，不为订单写运行状态。

SDK 不自动重试下单；超时返回未知结果，后续按撮合当前挂单重新计算，不重发原请求。取消本地订单日志后，不再宣称本地具备跨进程重启的持久发送去重；撮合订单和 client_id 为查询依据。没有把本地订单记录转存 Redis、消息队列或其他数据库。

本次不清空旧订单、撤单及快照，不改变迁移账本，不改模板、实例参数、控制版本或最终启停。网格仍用已有下单记录；development_only 合成成交保留原批次、消耗序号和去重。商户实时挂单继续从撮合观察读取，本地订单/撤单历史查询仅表示保留的旧记录。

验收同时检查 SDK 实际收到新挂单/撤单，以及本地订单、撤单和快照表完全不再增长或更新；不能只验证删除某一行数据库调用。
