# 独立受限平仓

历史存档：本页管理 HTTP/Web 的应用和交付工具已于 P14 移除；保留原设计与验收记录。后端领域、RPC 和历史迁移是否仍存在，以当前源码和 PROGRESS 为准。

[R08/R09](PRD.md)要求停止、撤单和平仓有各自授权、确认和结果。P07.67交付内部领域候选，P07.68–P07.69增加不可变确认及待处理账户屏障，P07.70提供内部受理/原键重放和当前viewer确认读取。P07.71增加持久任务及账户活动工作唯一约束，当前viewer可读取存储进度。P07.72提供当前所有者的内部认领仓储；尚无任务执行、最终下单授权、gRPC/HTTP或管理页面，不能发送订单或宣称平仓功能完成。实际验证见[P07.67](validation/P07-67.md)、[P07.68](validation/P07-68.md)、[P07.69](validation/P07-69.md)、[P07.70](validation/P07-70.md)、[P07.71](validation/P07-71.md)。

## 首版范围

明确确认`scope=account_instrument`、account_id和instrument_id；strategy_id只用于核对该账户当前唯一策略关联。持仓包括账户开仓起点和所有权威成交，不能把共享账户持仓虚构为某个策略的份额。首版拒绝共享账户，保留现有共享账户的其他交易能力；后续如支持账户批量平仓，须另行实现完整范围授权与保护。

只允许模拟现货且当前admin角色。先完成策略范围紧急撤单，再单独确认平仓：引用明确的持久SUCCEEDED/完整收录/完成时间证明，确认其关闭后的风险修订仍等于当前关闭状态。重新开启后再次关闭的风险修订、未完成或失败的旧任务都不能借用。此前撤单的操作者可以不同，平仓仍需自己的当前管理员会话、CSRF、幂等键、原因及审计。

人工确认包括独立风险修订、持仓投影修订、核心基础资产余额修订、当前基础资产数量和明确限价。数量单位为基础资产，价格为报价资产/基础资产，notional及限额为报价资产。所有接口将小数定义为string，Go内部使用decimal.Decimal；身份/修订保留完整int64。

## 候选计划门禁

纯函数`PlanAdminFlatten`只检查传入的内部快照，不能证明快照来源、当前会话或执行权限。后续仓储必须在金融事务及实际锁下重新验证：

- 模拟账户/交易对与唯一策略绑定、当前admin、原范围证明及独立风险关闭修订一致。
- 当前投影已经对账、源事实完整，确认的投影及核心余额修订一致；核心可用基础资产等于投影及人工确认数量，基础资产冻结为零。
- 当前账户全部未归结订单/资金义务和全部未归结出站提交为零，覆盖仍无OMS身份的UNKNOWN与核心孤单；不能只依靠旧任务成功或零挂单投影。
- 单笔数量、价格tick/数量lot、最小数量/金额及明确单笔金额上限全部满足。保持完整确认数量和限价；超过限额、非零尘埃或不对齐时明确拒绝，不能裁剪后宣称平仓。

非零余额只提出`REDUCE_ONLY_SELL`候选，SELL、reduce_only=true、GTC及确认限价/全量数量固定；报价费用沿用模拟核心正式冻结/成交结算。ledger可保留36位，仅当截到18位后数值完全相等时允许无损转成订单精度；非零余数被拒绝。零余额仍检查全部门禁，只返回`NO_ORDER`候选，不产生持久完成证明。

## 后续持久化与执行

P07.68的AdminAccountFlattening仅保存确认身份、原范围完成记录、风险/投影/核心余额修订、完整数量、限价及独立审计。数据库提交时重查当前admin/会话、唯一策略关联、模拟账户/产品、范围完成与仍关闭风险、当前余额/投影及源收录统计、全部已有义务和精度/限额；禁止改删历史、复用审计或同操作者请求键。迁移不补造请求，也不改变任何旧资金、风险或目标。结构检查不授予执行权。

P07.69增加schema36的持久账户屏障：现阶段每条确认都保持待处理，包括数量零和缺少工作进度的情况。提交时禁止管理员恢复、预算重新开启、缓存新增风险，以及创建/改变账户策略关联、参数/来源版本或配置激活；原风险减少及正常运行/租约字段不因此授予新风险。绑定/配置使用既有账户预算互斥，缓存授权沿既有核心账户锁顺序复核，不依赖进程锁或Nacos在线。延迟约束同时覆盖同一事务“先配置后确认”和相反顺序；新建/发布返回明确冲突，恢复返回原RECOVERY_DENIED，全部失败回滚。

屏障不补造工作或完成证明；以后只能经新的版本化迁移细化未归结判断，不能把缺行或零数量当作完成。P07.71新增活动任务唯一约束，最终交易授权仍待实现；该屏障不代替执行端fencing。实际验证见[P07.69](validation/P07-69.md)。

P07.70内部仓储借用唯一数据库，当前admin/会话及独立CSRF检查在任何键读取之前完成；金融锁下重读账户唯一关联、原范围证明、当前关闭修订/余额/对账/全量义务及精度/限额，再同事务写独立审计和不可变确认。角色、作用域、三项独立修订和完整数量/限价/原因都受校验；写失败或提交时失权整体回滚，错误不返回部分ID或私有数据库信息。

原键按操作者绑定全部规范化业务确认，小数按等值规范串计算指纹。历史重放仍要求当前管理员权限/CSRF；注销后旧令牌拒绝，同一用户真实重登录可取回同一原记录。历史重放不重算后来余额或再写审计；新键在已有待处理账户中冲突，四个同键并发只有一个效果。当前viewer通过只读RepeatableRead读取指定策略/确认，不重建投影、补账或推进工作；采样外的后续余额变化不改写历史确认。新确认仍只开启待处理保护；P07.71提供存储进度，最终交易授权仍未实现。

候选计划不含可提交的意图身份、幂等执行键、租约或最终fencing权限。P07.70已持久化管理员请求及审计并将原键绑定全部确认字段，当前权限下可重放历史确认；后续执行的UNKNOWN仍须沿原意图先查，不产生第二次卖单。受理后再由有所有权的业务执行者沿持久OMS/核心资金链路执行，最终交易路径验证专用、有限、不可挪用的风险减少授权。

待处理平仓必须与风险恢复、策略创建/配置变化、同账户出站命令互斥，防止唯一策略关联或零义务检查后产生新风险。计划失效、租约丢失、资金/事实不一致或部分成交均不能授权新增风险；实际成交继续入账，未知及未确认撤单保留预留。完成只能依靠当前权威余额、全量义务归结及持久证明；历史完成与后来余额分别观察，完成不自动重开风险。实际执行、终态证明及浏览器能力仍待实现，生产交易没有授权。


## 持久任务与存储进度

P07.71的schema37从Proto生成AdminAccountFlatteningTask，与确认一对一。新确认在同一数据库事务中由触发器初始化QUEUED/revision=1，owner/epoch/claimed_at均NULL；任何审计、确认或后续写入失败都不留下部分任务。旧schema36确认升级时也只补QUEUED；明确核验升级夹具未提前执行最新迁移，保留原确认、策略、资金和风险，重复迁移不重建任务。

数据库只允许QUEUED与ACTIVE，两者均待处理。禁止改删身份/范围、回退修订、重新入队或伪造完成；ACTIVE必须从已有任务推进，不能直接插入。账户上的partial unique index只允许一个ACTIVE，允许多个历史确认各自排队；并发竞争由PostgreSQL约束，不依赖进程锁。当前没有终态，不把零数量、缺任务或活动标记当作完成。

ACTIVATE及接管记录只表明最后一次持久认领：提交时使用数据库时钟复核实际StrategyLease的owner/epoch/expiry与StrategyInstance运行身份，接管只能提升epoch并保留同一任务。过期、伪造epoch或旧所有者回归均被拒绝；更新后至提交前失去租约也完整回滚。锁顺序保持既有策略在前、租约在后，避免等待策略时先占住当前执行者需要的租约；真实阻塞PID及NOWAIT回归核验此顺序。这些约束不检查或授予最终订单权限，P07.72提供内部认领仓储，仍无工作循环或OMS/核心下单旁路。

当前viewer在只读RR读取指定策略/确认对应的Progress，严格解码高位ID/修订、可空owner及时间。读取和确认原键重放不认领、补造任务或刷新所有权；注销后旧令牌读取拒绝，错误返回零结果。返回owner只是存储事实，不能证明查询回复抵达时租约仍有效。


## 当前所有者认领

P07.72的AdminFlattenWork只借用同一数据库，不创建池、goroutine、租约或网络资源。Claim要求有期限的context及完整策略LeaseToken，在ReadCommitted中先锁策略NO KEY UPDATE，再锁实际租约、任务和既有金融行；用数据库时钟检查租约owner/epoch/expiry与运行incarnation，不能只凭入参ExpiresAt或Nacos在线。再重读原确认、账户/产品/唯一策略、独立风险/投影/核心余额修订、原范围完成证明、精确数量/限价/对账/全账户义务和限额，失效不认领。

有效原确认属于已持久受理的明确范围；其操作者后来注销不撤回该历史确认。实际执行者凭自己当前策略所有权认领，不能用旧Bearer读取或重放管理请求。相同当前所有者重试不改任务ID、修订或认领时间，仍重核当前事实；高epoch接管保留同一任务并只增加一次认领修订。其他历史确认竞争同账户ACTIVE时返回明确冲突并保持QUEUED。

认领时间及更新时间同取数据库时钟，不混入宿主时间；新写入仍由schema37在COMMIT复核当前所有权。存储失败或更新后提交前租约失效返回零结果，任务、修订及同事务故障全部回滚；原所有权和任务随后可重新认领。该返回值仍只是最后存储认领的观察，不是持久订单授权；最终交易必须重新验证专用有限授权与实际owner/epoch。

本步不创建StrategyAction、OrderIntent、核心订单、冻结或预算预留，也不改策略目标/配置/状态或重开风险。仍待工作循环、显式意图关联、最终有限授权、UNKNOWN恢复及真实完成证明，见[P07.72](validation/P07-72.md)。
