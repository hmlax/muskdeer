# 独立受限平仓

[R08/R09](PRD.md)要求停止、撤单和平仓有各自授权、确认和结果。P07.67交付内部领域确认及纯计算候选计划，P07.68增加Proto生成的不可变确认结构与schema35；尚无受理仓储、执行授权、gRPC/HTTP或管理页面，不能发送订单或宣称平仓功能完成。实际验证见[P07.67](validation/P07-67.md)、[P07.68](validation/P07-68.md)。

## 首版范围

明确确认`scope=account_instrument`、account_id和instrument_id；strategy_id只用于核对该账户当前唯一策略关联。持仓包括账户开仓起点和所有权威成交，不能把共享账户持仓虚构为某个策略的份额。首版拒绝共享账户，保留现有共享账户的其他交易能力；后续如支持账户批量平仓，须另行实现完整范围授权与保护。

只允许模拟现货且当前admin角色。先完成策略范围紧急撤单，再单独确认平仓：引用明确的持久SUCCEEDED/完整收录/完成时间证明，确认其关闭后的风险修订仍等于当前关闭状态。重新开启后再次关闭的风险修订、未完成或失败的旧任务都不能借用。此前撤单的操作者可以不同，平仓仍需自己的当前管理员会话、CSRF、幂等键、原因及审计。

人工确认包括独立风险修订、持仓投影修订、核心基础资产余额修订、当前基础资产数量和明确限价。数量单位为基础资产，价格为报价资产/基础资产，notional及限额为报价资产。所有接口将小数定义为string，Go内部使用decimal.Decimal；身份/修订保留完整int64。

## 候选计划门禁

纯函数`PlanAdminFlatten`只检查传入的内部快照，不能证明快照来源、当前会话或执行权限。后续仓储必须在金融事务及实际锁下重新验证：

- 模拟账户/交易对与唯一策略绑定、当前admin、原范围证明及独立风险关闭修订一致。
- 当前投影已经对账、源事实完整，确认的投影及核心余额修订一致；核心可用基础资产等于投影及人工确认数量，基础资产冻结为零。
- 当前账户全部未归结订单/资金义务和全部未归结出站提交为零，覆盖仍无OMS身份的UNKNOWN与核心孤单；不能只依靠旧任务成功或零挂单投影。
- 单笔数量、价格tick/数量lot、最小数量/金额及明确单笔金额上限全部满足。保持完整确认数量和限价；超过限额、非零尘埃或不对齐时明确拒绝，不能裁剪后宣称平仓。

非零余额只提出`REDUCE_ONLY_SELL`候选，SELL、reduce_only=true、GTC及确认限价/全量数量固定；报价费用沿用模拟核心正式冻结/成交结算。ledger可保留36位，仅当截到18位后数值完全相等时允许无损转成订单精度；非零余数被拒绝。零余额仍检查全部门禁，只返回`NO_ORDER`候选，不产生持久完成证明。

## 后续持久化与执行

P07.68的AdminAccountFlattening仅保存确认身份、原范围完成记录、风险/投影/核心余额修订、完整数量、限价及独立审计。数据库提交时重查当前admin/会话、唯一策略关联、模拟账户/产品、范围完成与仍关闭风险、当前余额/投影及源收录统计、全部已有义务和精度/限额；禁止改删历史、复用审计或同操作者请求键。迁移不补造请求，也不改变任何旧资金、风险或目标。结构检查不授予执行权。

P07.69增加schema36的持久账户屏障：现阶段每条确认都保持待处理，包括数量零和缺少工作进度的情况。提交时禁止管理员恢复、预算重新开启、缓存新增风险，以及创建/改变账户策略关联、参数/来源版本或配置激活；原风险减少及正常运行/租约字段不因此授予新风险。绑定/配置使用既有账户预算互斥，缓存授权沿既有核心账户锁顺序复核，不依赖进程锁或Nacos在线。延迟约束同时覆盖同一事务“先配置后确认”和相反顺序；新建/发布返回明确冲突，恢复返回原RECOVERY_DENIED，全部失败回滚。

屏障不补造工作或完成证明；以后只能经新的版本化迁移细化未归结判断，不能把缺行或零数量当作完成。受理/重放仓储、活动工作唯一性和最终交易授权仍待实现；该屏障不代替执行端fencing。实际验证见[P07.69](validation/P07-69.md)。

候选计划不含可提交的意图身份、幂等执行键、租约或最终fencing权限。后续步骤须先持久化管理员请求及审计，原键绑定全部确认字段；当前权限下重放历史结果，UNKNOWN沿原意图先查，不产生第二次卖单。受理后再由有所有权的业务执行者沿持久OMS/核心资金链路执行，最终交易路径验证专用、有限、不可挪用的风险减少授权。

待处理平仓必须与风险恢复、策略创建/配置变化、同账户出站命令互斥，防止唯一策略关联或零义务检查后产生新风险。计划失效、租约丢失、资金/事实不一致或部分成交均不能授权新增风险；实际成交继续入账，未知及未确认撤单保留预留。完成只能依靠当前权威余额、全量义务归结及持久证明；历史完成与后来余额分别观察，完成不自动重开风险。所有这些持久/执行/浏览器能力仍待实现，生产交易没有授权。
