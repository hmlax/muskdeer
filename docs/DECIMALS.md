# 十进制业务边界

P03.1 已提供 `internal/domain` 的纯业务值对象；只依赖标准库和已固定的 decimal v1.6.0，没有 ORM、网络或框架类型。持久化与线协议保持独立，后续适配器显式映射生成的 Proto。

## 解析与精度

ParseDecimal 从接口 string 直接解析，不经浮点。每个字段必须提供 DecimalRule：整数位 1..38、小数位 0..38、是否允许负数/零；这是有界解析器的能力范围，具体资产/字段必须选择与数据库列兼容的精度，不能统一套最大值。未指定规则拒绝输入。

仅允许 ASCII 十进制整数及可选小数部分，不接受空白、加号、前导零、多点、空小数部分、科学记数法、NaN/Inf、Unicode 数字。负号、负零和零分别受规则控制；末尾小数零也计入输入 scale。decimal.String() 输出规范十进制字符串，允许去掉无意义末尾零。

价格、数量、币种金额、费率、比例的单位和范围由对应合同声明；持仓/损益可以显式允许负数，价格与下单数量不得允许零。当前纯解析器不冒充价格范围、手续费上限、资产元数据或风险额度校验。

## tick/lot 量化

RoundPrice 对正数按 BUY 向下、SELL 向上取 tick；RoundQuantity 对正数量向下取 lot。采用 QuoRem(step, 0) 的整数商/余数，避免 decimal 全局除法精度预先舍入后跨越报价边界。不修改库全局变量，所有比较及乘加均用 decimal。

计算输入的 exponent 和系数位数有界，拒绝零/负增量及未指定 side。小于一个 step 的向下量化可能得到零，调用方必须在预留/提交前重新检查正数、tick/lot 对齐及最小金额；订单合同和执行校验在下一步实现。

## 来源值对象

MarketSource 集中定义 binance、okx、bitget、bybit 及用户原始 bitgit 别名；解析只规范大小写、外侧空白及这一明确别名。ValidateSelection 区分首批合格标识与候选，未知/空值不设置默认值、不换源。该检查只决定首批来源资格，适配器是否启用、交易对支持及实时健康必须由后续运行层另行验证；不是已连接交易所的声明。

实际验证见 [P03.1](validation/P03-01.md)。
