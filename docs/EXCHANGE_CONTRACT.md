# 现有交易所接入合同与缺失资料

状态：2026-11-03 已取得 Himalaya 本地开发仓库/Proto 和可用只读接口。用户确认以测试资金接入其 ONE_WAY 线性永续撮合，先补齐两边交易合同，再由 Muskdeer 接管 BTC/ETH；当前运行的 Muskdeer 仍是现货模拟器，不能用改交易对配置冒充真实接通。以下是验收要求，不代表原生网关已经具备全部能力。

## Himalaya 开发接入

旧启动脚本的 BTCUSDT/ETHUSDT 分配独立测试用户，按每侧 20 档、源数量 0.1、200ms、最高 10 倍杠杆启动。它使用 USDM 永续行情和保证金账户，与既有 Go 现货余额/结算模型不同。已只读确认交易对网格、正的测试余额、旧挂单和仓位；不在代码/文档中保存认证凭据或账户资金明细。

原生 Place/OpenPosition 的 client_id 当前仅有关联存储证据，未确认同键去重；每次原生提交分配新 order_id。请求没有客户端策略/执行所有权字段，现有撮合恢复/撤单 fence 不能冒充生产者 epoch。因此需新增独立开发 Gateway 合同，并在最终撮合执行处校验账户执行者和策略控制者两个作用域。稳定 client_id 必须关联唯一原生命令；未知结果先查，不能仅因列表暂时不存在而重发或释放风险。

新 typed 合同见 [Himalaya Gateway](../deer/proto/rpc/himalaya/v1/gateway.proto)。能力握手必须确认开发测试资金、持久幂等、最终 fencing、按客户端键查询、post-only、ONE_WAY 永续与失联撤单；缺失任一项则 Go 客户端拒绝暴露交易能力。协议和独立组件验证不等于真实服务已实现或已接管。

## 必需能力
| 能力 | 核心字段/行为 | 缺失影响 |
|---|---|---|
| 交易对元数据 | tick、lot、min_notional、状态、币种 | 无法正确报价 |
| 账户余额 | available、frozen、版本/时间 | 无法核实资金 |
| 下单 | client_order_id、账户、方向、数量、价格、TIF、所有权 epoch | 无法真实执行 |
| 订单查询 | 按本地关联标识/核心订单 ID 查询，明确不存在语义 | 无法解决 UNKNOWN |
| 撤单/批撤 | 请求接受与最终完成分离，支持部分成功 | 无法安全停止报价 |
| 有效订单快照 | 可分页及一致性边界 | 无法接管恢复 |
| 订单成交流 | 唯一成交标识、序列、断点恢复或拉取补齐 | 无法可靠投影 |
| 历史成交查询 | 起止范围、分页、去重语义 | 无法对账和重建 |
| STP | 同一自营主体跨账户防自成交 | 无法保证自成交隔离 |
| 失联撤单 | 服务端心跳 TTL、作用域、撤单结果 | 进程失效时旧报价风险 |
| fencing | 交易网关原子验证 epoch，拒绝旧 owner | 严格多节点接管保证受限 |

## 需要提供的资料
仓库/接口文档或 Proto、认证签名规范、测试环境、专用测试账户、限流、错误码、client_order_id 唯一性作用域及保留期、事件序列/重连规则、下单精度、资金冻结及手续费规则。密钥通过本地安全配置注入，不能写入此文档或聊天日志。

## 模拟器
实现上述合同的可控子集并声明能力表。支持固定种子、部分成交、延迟响应、实际成功但响应丢失、撤单竞态、重复回报、乱序、流缺口、余额不足和 epoch 失效。测试由显式事件驱动，不通过长期 sleep 期待随机成交。
模拟器不得自动承诺真实平台支持 fencing、STP 或查询幂等。真实适配器单独运行合同测试，输出通过/不支持/未知的能力矩阵。
